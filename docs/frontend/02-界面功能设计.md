本设计以你上传的 TraeWork 截图为准，用**三栏布局** + **隐藏式右栏**搭建，严格复刻可见部分，
并预留"完全访问 / 附件 / 模型 / 快捷命令"等交互位。后端当前只能提供"对话 + 会话 + 目标 + 待办 + 技能 + 工具"，

### 2.3 任务列表（核心可交互区）

- 头部：`任务列表` + 右侧 `＊`（新建）+ `≡`（筛选/排序）。

- 当前工程名：固定显示「默认」（`tasktree-project`，硬编码文案；早期版本显示后端 root 目录名 `learn-claude-code-main`，已改为统一「默认」）。

- 树形任务项：可展开/收起子任务，点击切到对应会话/上下文。

- 视觉态：当前激活会话高亮（`active` 类，随 `activeSession` 状态）；早期版本把末项置灰的 `muted` 逻辑已移除（会话可任意切换后该标记失去意义）。

- **数据来源（本期）**：后端 `sessions_list` 会话接口（`index.jsonl` 元数据 + 消息计数）拼出任务列表；支持点击 `switch_session`。真正的 task/todo 树要后端新增接口，列入增量；本期先展示「会话列表」作为任务树的近似。

- **标题展示**：会话标题来自后端元数据（首条消息后并行自动生成 / 用户手动重命名），无标题回退显示 `session_<num>`；右侧保留消息计数 badge。详见 07 篇。

- **会话菜单**：会话行 hover 显示 `⋯` 三点按钮，点击弹出菜单；**右键菜单**与三点按钮共用同一个 `SessionMenu` 组件。菜单项：`重命名`（行内原位变输入框，Enter 提交 / Esc 取消 / blur 提交）、`删除`（软删除移入回收站，toast 提示；删除当前激活会话则前端同步回空态）。流式进行中菜单项禁用。

- **切换会话**：点击任务项 → 前端`立即高亮并直接投影到该会话的消息缓冲`（后台会话继续执行、输出不受影响），同时发 `session_switch` 给后端回放该会话历史（运行中的会话以实时缓冲为准，不回放磁盘快照）。切换失败（会话不存在）后端回 `error` 事件。

- **会话状态指示（侧边栏）**：任务项左侧渲染一枚状态点——**运行中**青色脉冲点（`session_status: running` 或 `background`，后者 title 为"后台任务执行中"），**后台完成**绿色实心未读点（`session_status: done/stopped` 且当前显示的不是它；切到该会话即清除）。**断线重连后的状态复位**：连接恢复（`disconnected → connected`）时前端清空全部运行态（`runningSessions` / `bgSessions` / `isSending`），随后由后端在新连接上重放各会话当前 `session_status`（running/background）重新点亮真实运行中的会话——既消除断连期间的状态残留（永远转圈的僵尸会话），又保证后台执行指示不丢（协议细节见 03 篇 5.2）。

- **执行状态自动恢复（渲染进程刷新补偿）**：运行态（`runningSessions` / `bgSessions` / `connection`）只存渲染进程内存，Vite HMR / Cmd+R 刷新后归零，而主进程 WS 连接不重建、后端"新连接重放"覆盖不到——历史上表现为"子智能体还在后台跑，前端运行指示/停止按钮却消失"。现渲染进程挂载时主动 `getConnectionStatus()` 恢复连接态，并在 `connected` 时调 `queryStatus()`（IPC → 后端 `status_query` 命令）拉取仍在运行会话的 `session_status` 重放，自动重新点亮运行指示与后台脉冲点（协议细节见 03 篇 5.2 `status_query`）。

- **新建语义（惰性会话）**：`＊`（或快捷操作区「新建任务」）**只是前端行为**——清空消息流、`activeSession` 置 `null`、回到欢迎空态，**不**调后端、**不**产生 `session_N.jsonl`。后端真正的会话文件在该"草稿"的首条消息发送时才创建（chat 不带 `num`，后端收到后确定性领号新建会话并回发 `session` 信封，前端据此把草稿缓冲迁移到正式会话缓冲并更新 `activeSession` 与列表）。这样避免了"每次打开窗口都多一个空会话"的副作用。首条消息到达即并行生成会话标题（不等首轮结束，见 07 篇）。

## 3. 中央聊天面板

### 3.1 空态（无消息时）

居中品牌标识：`</> Anything for You`（logo 图标 + 大号粗体文字，即"为您做任何事情"的英文版）。
下方即是输入区（见 3.3）。早期版本曾在此处置放四个快捷命令 chips，已在优化迭代中移除。

### 3.2 消息流（有消息后）

每条消息按角色渲染：

| 角色             | 样式                                       |
| -------------- | ---------------------------------------- |
| User           | 浅色卡片/气泡，靠右或正常展示                          |
| Assistant      | 白底，含 `thinking`（可选收起）与正文两段               |
| Tool Call      | 收起式工具条（齿轮图标 + 工具名 + 参数摘要 + 状态），本期做成只读折叠条 |
| 子智能体（SubAgent） | 机器人头图标折叠块（见下），挂在所属 assistant 消息下         |

- **thinking（思考）**：来自 `thinking_delta`，灰色细体，可折叠；折叠行以**大脑图标**标识「思考过程」（区别于工具执行条的齿轮图标），点击行可展开/收起灰色思考正文。思考过程默认折叠，为避免用户误以为模型假死，`thinking_delta` 流式输出期间（`thinkingActive=true`）在「思考过程」文字右侧显示**小型转圈图标**（与工具执行条运行态同一 spinner 样式），提示模型正在思考；思考完成（开始输出正文 / 调用工具 / `turn_end`）后 `thinkingActive` 置 false，图标消失。历史回放消息为静态已完成态，不显示转圈图标。

- **子智能体执行块**：当主智能体调用 `sub_agent` 工具时，子智能体的执行过程以**折叠块**展示在其 assistant 消息下：

  - 块头部：**机器人头图标** + 任务名 + 右侧状态区（状态徽标 / 耗时 / 状态图标）+ 折叠箭头；点击头部可展开/收起。四种状态：
    **执行中**（紫色「执行中」徽标 + 脉冲转圈）、**已完成**（勾 + 耗时如 `12s`）、
    **失败**（红色「失败」徽标 + 红叉，边框着色，展开可见失败原因）、
    **已中断**（黄色「已中断」徽标 + 停止图标，表示进程被强杀、只留下启动记录）。

  - 块内容：子智能体的**思考过程**（大脑图标，可折叠）与**工具执行**（齿轮图标折叠条），样式与外层一致，但整体折叠在子智能体块下；执行中且尚无产出时显示「子智能体正在准备…」占位。**子智能体返回给主智能体的答复正文不在卡片中展示**——那是给主智能体的结果，不是给用户的内容（避免与主智能体的复述重复）。

  - 数据来源：子智能体转发的 `thinking_delta` / `tool_call*` 事件（携带 `subagent_id` 标识），由前端路由进对应块；块以 `sub_agent_start` 创建、`sub_agent_end` 收尾。并行多个子智能体时按 `subagent_id` 各自成块；子智能体内部并行多个工具调用时按 `tool_id` 各自成行（不串台）。

  - **唯一锚点规则**：卡片永远挂在**发起它的那条 assistant 消息**下——用 `sub_agent_start` 携带的 `tool_id`（发起方主工具调用 id）定位宿主消息；该 `subagent_id` 的块一旦建立，其后续事件沿用同一宿主（子智能体的 `thinking`/`tool_*` 事件不带该 id，只能靠这一条保证不被挂到别的 assistant 上）。实时与回放共用同一规则 → **切换会话前后卡片位置不跳变**（历史缺陷：实时挂在末尾新建气泡、回放挂在发起方消息，切会话时位置会跳）。

  - **持久化与回放**：子智能体执行过程持久化到**旁路文件** `session_N.subagents.jsonl`（与主 jsonl 物理隔离，见 03 篇 2.1.1），切会话/重开后由 `session_history` 的 `subagents` 字段恢复折叠块（含状态与耗时）；**但不进入主模型上下文**——主 LLM 只收到子智能体返回的摘要。启动时先落一条 `running` 占位记录，因此进程被强杀后历史里仍留有「已中断」痕迹。

  - **一致展示规则**：不管实时执行还是历史回放，`sub_agent` 永远只以折叠块（机器人头图标卡片）形式展示：

    - 实时流式：`sub_agent_start` 新建折叠块，`tool_call_start` 不渲染普通工具条（但记录锚点 id）；

    - 历史回放：前端 `historyToMessage` 把 `toolCalls` 里的 `sub_agent` 自动剥离出来转成折叠块；后端有旁路记录则用后端记录，后端缺失（老数据）则派生一张占位卡片；

  - **一致展示效果**：实时流与回放两条通道展示同一结构，回放块为已完成态（无流式光标）；无论会话完成多久、来回切换多少次，永远保持折叠卡片展示，不退化回普通工具条。

  - 后台子智能体（`run_in_background=true`）：transcript 在后台任务完成时**立即落盘到旁路文件**，切走切回就能看到完整折叠块，无需等下次用户输入；完成时主 turn 若已结束，卡片仍挂回**发起它的那条 assistant**（而非末尾新建气泡）。

  - **后台完成自动总结**：后台子智能体跑完后，主智能体会被**自动唤醒续一轮**（后端行为，见 03 篇 1.1），拿到 `<task_notification>` 结果后给出最终总结回复——不会停在"已派发后台任务，稍等片刻"的占位话术上。前端无需为这一轮做任何特殊处理：它只是一次普通的 `running` 态 turn（复用同一消息缓冲的追加逻辑），事件流照常渲染。

- **正文 Markdown 渲染**：`content_delta` 汇聚后，用轻量 markdown 渲染（代码高亮 + 代码块）。

- **流式光标**：生成中在末尾显示闪烁光标。

- **usage 展示**（可选）：`turn_end` 时在消息尾部显示 token 统计小字。

- **自动滚动跟随（贴底策略）**：消息容器 `.msglist` 只在用户「贴底」时才自动跟随滚到最新内容，避免流式输出高频触发滚动导致画面上下跳动：

  - 贴底判定：滚动条距容器底部 `48px` 以内视为贴底；用户向上翻看超过该距离即视为脱离跟随，此后流式输出不再抢占滚动位置，可自由回看历史；

  - 用户滚回底部附近自动恢复跟随；

  - 切换会话（含首次加载/历史回放）时强制重置为贴底，回到最新消息；

  - 滚动实现直接赋值 `scrollTop`（即时吸底），不使用 `scrollIntoView({ behavior: 'smooth' })`——流式输出时每个 `content_delta` 都会刷新消息缓冲，smooth 动画被高频重复触发会叠加补偿滚动，是画面上下抖动的根源。

### 3.3 输入区（中央核心组件）

结构（自上而下）三行：

```
┌────────────────────────────────────────────────────────────────┐
│ 多行 textarea（自动增高，上限高度后滚动）                          │
├────────────────────────────────────────────────────────────────┤
│ [+] 完全访问 ▼   [📎] [📊]   DeepSeek-V4-Flash 正... ▼  [◍上下文]  [⬆] │
└────────────────────────────────────────────────────────────────┘
│ 💻 本地 ▼    📁 learn-claude-code-... ▼                          │
└────────────────────────────────────────────────────────────────┘
```

- **第一行**：多行输入框，`Enter` 发送 / `Shift+Enter` 换行。

- **第二行（工具栏）**：

  - `+`：添加内容（占位）

  - `完全访问`：权限下拉（后端有权限校验能力，本期做展示/占位）

  - `📎` 附件、`📊` 图片：占位（后端暂不支持直接传文件，列增量）

  - **模型下拉**：显示当前所选模型名（默认 `DeepSeek-V4-Flash`）；点击展开**已启用模型**列表（数据源 `agentStore.llmConfig`，实时同步设置页），点击项即切换激活模型（热生效）。每一项**悬浮弹出**逐模型配置面板（思考强度/更大上下文，见上「模型下拉悬浮配置面板」）。

  - **上下文使用量圆圈指示器**：位于模型下拉与发送按钮之间。仅当**选中一个会话**时显示（草稿/空态隐藏）；为一枚**纯环**（环内不显示数字），环长按「已用百分比」着色（<70% 绿 / 70%\~90% 黄 / >90% 红）。鼠标悬浮（**自定义 tooltip**，非原生 `title`——原生在部分环境不响应/滞后）于圆上即时弹出气泡展示 `已用 X / 总计 Y tokens（Z%）`：`Y`（上下文支持多少）跟当前模型走，取自公共模型元数据 `max_context`（扩展则是 `max_context_extended`）；`X` 来自后端 `context_stats` 事件（每轮结束/切会话后推送，见 03 篇 2.4）。`🔔` 铃铛占位图标已移除，圆圈直接位于模型下拉右侧。

  - **模型下拉悬浮配置面板**：模型下拉的每一项在鼠标悬浮（`hover`）时，右侧弹出**逐模型配置面板**（不改变选中模型，仅配置当前会话覆盖参数，需再点击该项才切换模型）：

    ```
    ┌─────────────────┐
    │  思考强度         │
    │  轻   高  极高    │
    ├─────────────────┤
    │  更大上下文       │
    │  关闭   开启      │
    └─────────────────┘
    ```

    - 两个选项均读公共模型元数据：思考强度项枚举 `thinking_strengths`，默认高亮 `default_thinking`；更大上下文开关只在该模型有 `max_context_extended` 且（若已扩展）显示为开启时可选。参数**按模型 id 分别保存**（前端 `overridesByModel` map / 会话元数据 `overrides` map）：每个模型独立存取，悬浮某模型时只显示该模型自己的参数，改动只写该模型，不串改其它模型。

    - 改动即**当前会话下一轮生效**：写入前端 `overridesByModel[modelId]`（内存态）并 `session_model` 持久化进当前会话元数据；随下次 `chat.overrides` 带给后端，不在设置里落盘、不影响其它会话。

    - **无会话也可配置**：欢迎空态/新会话（未选任何会话）同样可悬浮弹出该面板预设参数；此时发送首条消息会携带这套 `overrides`，让新会话第一轮就按预设的思考强度与更大上下文执行。

  - **新建会话继承**（主流智能体行为）：在任一会话中最后**选中**的模型（写入会话元数据 `model_id`）与**按模型参数**（`overridesByModel`/`lastOverridesByModel`）会被前端记录。「新建任务」时自动**预选**该模型并**保留**每个模型的参数，收到 `session` 信封后写入新会话元数据——新会话默认按上一会话的模型与对应参数执行。历史会话仍是**每会话独立**：切换时按各自元数据恢复（`model_id`/按模型 `overrides` 的 map），互不影响。

  - `⬆`：发送按钮（紫→蓝渐变，圆角方钮）。**当前激活会话正在执行时**（`runningSessions` 含 `activeSession`，即 `isSending`），其**变成一个可点击的** **`■ 停止`** **按钮**，点击仅停止当前显示会话正在执行的那一轮，其它后台会话不受影响。

- **第三行（上下文）**：`💻 本地` 与 `📁 工程目录`，本期固定展示，行为列增量。

## 4. 设计系统（Design Tokens）

统一管理在 CSS 变量，避免散落魔法值。定义于 `src/renderer/src/styles/tokens.css`。

```css
:root {
  /* 色板 */
  --color-bg-main: #ffffff;          /* 主内容白底 */
  --color-bg-sidebar: #f5f5f5;       /* 侧边栏浅灰 */
  --color-bg-hover: rgba(0,0,0,0.05);
  --color-border: #e5e5e5;
  --color-text-primary: #1f1f1f;     /* 主文字 */
```

### 样式规范要点

- 扁平、圆角（`--radius-md`）、细边框（`--color-border`）、弱阴影。

- 主行动按钮用 `--color-action-grad` 渐变；普通按钮灰底。

- 侧边栏 `--color-bg-sidebar`，主区 `--color-bg-main`，分隔用 `--color-border`。

- macOS 风格：顶部留系统栏，无额外重边框。

### 全局 Toast 规范

- 组件：`@components/common/Toast`，挂载于 `App`，数据源 `agentStore.toast / toastType`。

- 位置：**窗口顶部居中**（`position: fixed; top: var(--sp-4); left: 50%`），深色底白字，error 态换 `--color-danger` 底色。

- 自动消失：**所有 toast 都必须自动消失**，统一走 `agentStore.ts` 导出的 `showToast(msg, type, ms)`（info 默认 3000ms，error 默认 4000ms）；模块级计时器在重复触发时重置，避免旧计时器提前清掉新提示。禁止直接 `setState({ toast })` 绕过计时器（会复现「提示永不消失」的 bug）。

- 触发来源：保存模型配置结果（`saveLlConfig`）、后端 `llm_config` / `error` 事件、侧边栏快捷操作占位提示（`QuickActions`）。
