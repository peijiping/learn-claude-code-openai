# 02 - 界面功能设计（TraeWork 复刻）

本设计以你上传的 TraeWork 截图为准，用**三栏布局** + **隐藏式右栏**搭建，严格复刻可见部分，
并预留"完全访问 / 模型 / 快捷命令"等交互位（附件/图片占位图标已移除）。后端当前只能提供"对话 + 会话 + 目标 + 待办 + 技能 + 工具"，
因此本文件**优先覆盖这些可达功能**，其余（模型管理、历史管理等）列为占位/后续增量。

├───────────┬─────────────────────────────────────────────┬──────┤
│           │                                             │      │
│  左侧边栏  │              中央聊天面板                     │ 右栏  │

│       状态条 (可选：连接状态 / token)                              │
└────────────────────────────────────────────────────────────────┘
```

- **窗口标题栏（2026-09-23 改为自绘）**：原生标题栏隐去（主进程
  `titleBarStyle: 'hidden'`），40px 的 `.titlebar` 由渲染层画 —— 所以"窗口标题"
  这件事**不再是 CSS 之外的黑盒**：`个人AI助手` 居中，右栏开关就在它的右端
  （窗体右上角，右内边距 16px），左侧 240px 与侧边栏同色（macOS 原生交通灯正好落在
  这段灰底上，位置由主进程 `trafficLightPosition: {x:16,y:14}` 对齐栏高中线）。
  整条栏**看着**都是拖拽区，但实现上是三块 `.titlebar-drag` 填充块（左翼 / 标题 / 开关左侧），
  即 **`.titlebar` 自身不设 `drag`** —— 保证开关那 26×26 里没有任何拖拽矩形
  （"整层 drag + 按钮 `no-drag`"会让点击依赖浏览器做矩形差集，不同步时 mousedown 被当成拖窗，
  `click` 根本不派发；2026-09-23 实测"点得开、点不关"即此坑）；
  Windows/Linux 走 `titleBarOverlay`（系统按钮由系统画，右侧留白 138px）。
  细节与坑见 **`19-右侧面板（文件与变更）.md`** §3.3。

- 左侧边栏固定约 240px（**不可折叠**：`.sidebar` 恒 `width: var(--sidebar-width)`，
  标题栏左侧那段灰底也按同一变量画，两者必须同宽）。

- **右栏**（默认 360px，可拖拽 280–720px）是**会话私有的多标签工作区**，2026-09-23 落地：
  一个会话一份实例，开没开、开了几个标签、哪个激活都随会话走，**会话间互不干扰**。
  本期含 `文件`（目录树 + 预览）与 `变更`（git 四分组 + 内联 diff）两个视图，
  `终端`/`浏览器` 在「+」菜单里置灰占位。详见 **`19-右侧面板（文件与变更）.md`** 与本文 §7。

- **客户端标题**：窗口/标签标题为 `个人AI助手`（`src/renderer/index.html` 的 `<title>`，经优化迭代调整）。

  （首条消息随 `chat.project_id` 带上，见 03 篇）；目录不可用时行变淡 + `!` 徽标 + 禁用 `+`。

  菜单里同时说明"仅删元数据（含 N 条会话），真实目录保留"；默认空间没有可管理项，不弹菜单。

- **空间级状态上浮**：子会话的运行状态汇总为该空间行的脉冲点、未读条数汇总为橙色徽标
  —— 折叠状态下也要能看出"这个空间里还有活没干完 / 有新消息"。

- **会话 15 条折叠**：每空间默认只显示最新 15 条（`SESSION_PREVIEW_LIMIT`），
  末尾给「展开全部 N 条」/「收起」入口；排序沿用后端的"最后修改时间倒序"，前端不二次排序。

- 视觉态：当前激活会话高亮（`active` 类，随 `activeSession` 状态）；早期版本把末项置灰的 `muted` 逻辑已移除（会话可任意切换后该标记失去意义）。

- **数据来源（本期）**：`sessions` 信封（后端全空间合并，每条带 `project`）+ `projects` 信封
  （空间元数据与 `active`）；点击切会话走 `session_switch`。

- **标题展示**：会话标题来自后端元数据（**简单两段式**：首条消息前 30 字默认标题 + 首轮结束后 LLM 总结精炼 ≤20 字；或用户手动重命名），无标题回退显示 `session_<num>`，不再显示消息计数 badge（消息数与列表性能解耦）。详见 07 篇。

- **会话菜单**：会话行 hover 显示 `⋯` 三点按钮，点击弹出菜单；**右键菜单**与三点按钮共用同一个 `SessionMenu` 组件。菜单项：`重命名`（行内原位变输入框，Enter 提交 / Esc 取消 / blur 提交）、`归档`（软删除，toast「已归档，可在设置 → 归档中还原」；归档当前激活会话则前端同步回空态）。流式进行中菜单项禁用。

- **悬停信息卡（SessionTooltip）**：鼠标悬停会话行时，在行右缘弹出信息卡展示五项会话基本数据——**完整标题**（不截断）、**所属项目**（工作空间，由 `project` id 映射为名称）、**总 token 消耗**、**缓存命中率**（百分比）、**最后更新时间**。数据全部来自会话元数据（`list_sessions` 透传 `project` / `usage_totals`），无额外请求；卡片纯展示（`pointer-events: none`）不拦截鼠标，`z-index` 低于弹出菜单。详见 07 篇 2.6。

- **切换会话**：点击任务项 → 前端`立即高亮并直接投影到该会话的消息缓冲`（后台会话继续执行、输出不受影响），同时发 `session_switch` 给后端回放该会话历史（运行中的会话以实时缓冲为准，不回放磁盘快照）。切换失败（会话不存在）后端回 `error` 事件。**切到别的空间的会话时，前端同步 `project_open`**，让后端"活动空间"跟上（否则下一次 `projects` 广播会把 chip 拉回旧空间）。

- **会话状态指示（侧边栏）**：任务项左侧渲染一枚状态点——**运行中**青色脉冲点（`session_status: running` 或 `background`，后者 title 为"后台任务执行中"），**后台完成**绿色实心未读点（`session_status: done/stopped` 且当前显示的不是它；切到该会话即清除）。**断线重连后的状态复位**：连接恢复（`disconnected → connected`）时前端清空全部运行态（`runningSessions` / `bgSessions` / `isSending`），随后由后端在新连接上重放各会话当前 `session_status`（running/background）重新点亮真实运行中的会话——既消除断连期间的状态残留（永远转圈的僵尸会话），又保证后台执行指示不丢（协议细节见 03 篇 5.2）。

- **执行状态自动恢复（渲染进程刷新补偿）**：运行态（`runningSessions` / `bgSessions` / `connection`）只存渲染进程内存，Vite HMR / Cmd+R 刷新后归零，而主进程 WS 连接不重建、后端"新连接重放"覆盖不到——历史上表现为"子智能体还在后台跑，前端运行指示/停止按钮却消失"。现渲染进程挂载时主动 `getConnectionStatus()` 恢复连接态，并在 `connected` 时调 `queryStatus()`（IPC → 后端 `status_query` 命令）拉取仍在运行会话的 `session_status` 重放，自动重新点亮运行指示与后台脉冲点（协议细节见 03 篇 5.2 `status_query`）。

- **新建语义（惰性会话）**：`＊`（或快捷操作区「新建任务」）**只是前端行为**——清空消息流、`activeSession` 置 `null`、回到欢迎空态，**不**调后端、**不**产生 `session_N.jsonl`。后端真正的会话文件在该"草稿"的首条消息发送时才创建（chat 不带 `num`，后端收到后确定性领号新建会话并回发 `session` 信封，前端据此把草稿缓冲迁移到正式会话缓冲并更新 `activeSession` 与列表）。这样避免了"每次打开窗口都多一个空会话"的副作用。新建会话即写首条消息前 30 字默认标题，首轮结束后 LLM 精炼 ≤20 字（简单两段式，见 07 篇）。

## 3. 中央聊天面板

### 3.1 空态（无消息时）

居中品牌标识：`</> Anything for You`（logo 图标 + 大号粗体文字，即"为您做任何事情"的英文版）。
下方即是输入区（见 3.3）。早期版本曾在此处置放四个快捷命令 chips，已在优化迭代中移除。

### 3.2 消息流（有消息后）

- **对话区宽度（消息流 + 输入区统一）**：消息内容列 `.msglist` 与输入区 `.composer-wrap` 均设 `max-width: 940px; width: 100%; margin: 0 auto`。窗口（扣除侧边栏后）宽于 940px 时对话区**居中固定**不再变宽；窄于 940px 时**随窗口收缩**。默认窗口 1180px（侧边栏 240px）下对话区正好 940px，视觉宽度与改前一致。

- **消息区两层结构（2026-09-20 改造，滚轮热区）**：消息流拆成「滚动视口 `.msgscroll` + 内容列 `.msglist`」两层——

  ```
  .chat (flex column)
   └── .msgscroll   flex:1 · min-height:0 · width:100% · overflow-y:auto  ← 滚动层（占满对话区全宽）
        └── .msglist   width:100% · max-width:940px · margin:0 auto        ← 内容层（不滚动）
             └── 每条消息 .msg-row
  ```

  - **改造原因（历史缺陷）**：此前 `.msglist` 单层既做滚动容器又限宽 940px，导致**滚轮热区只有 940px 宽**——窗口宽于 940px 时，鼠标移到内容列两侧的空白处（窗口留白）滚轮完全无响应，只有指针落在文本上才能滚动，与主流智能体客户端（鼠标在对话区域内任意位置都可滚动）的观感不符。
  - **改造后**：滚动职责全部上移到 `.msgscroll`（宽度 100%，不限宽），滚轮落在对话区**任意位置**（含两侧空白）都能上下滚动对话记录；`.msglist` 退化为纯内容列，只负责限宽 / 居中 / 内边距。
  - **不变量**：滚动位置、`scrollHeight` 贴底判定、会话切换强制吸底一律以 `.msgscroll` 为准（`MessageList` 的 `containerRef` 挂在外层视口）；`.msglist` 的 940px 宽度、居中、`padding` 与改前逐像素一致，视觉零变化。

- **对话区滚动条隐藏**：消息视口 `.msgscroll`、深度思考框 `.thinking-content`、输入框 `.composer-input` 均隐藏滚动条（`scrollbar-width: none` + `::-webkit-scrollbar { display: none }`），滚动功能保留（滚轮 / 触控板正常滚动）。

- **消息内嵌滚动区域（2026-09-20 梳理）**：对话记录内的元素若自带滚动条，会**抢占**该位置的滚轮手势，因此按「能否纵向滚动」分两类处理：
  - **只横向滚动**（滚轮纵向照常透传给对话区）：代码块 `.markdown-body pre` 显式 `overflow-x: auto; overflow-y: hidden`——`overflow-y: hidden` 使其不再是纵向滚动容器，鼠标停在代码块上上下滚轮依旧滚动对话记录（高度 auto，内容不会被裁）；超宽表格由 `.table-scroll` 包裹（`MessageItem` 经 `react-markdown` 的 `components.table` 注入），列多时表格**自身**横向滚动、不撑宽对话区。
  - **纵向可滚动（保留，属设计行为）**：深度思考框 `.thinking-content`（`max-height` 自适应框，内容超出时框内滚动）。此时滚轮先滚框内、滚到边界后由浏览器**链式滚动**接管、继续带动外层 `.msgscroll`（`.msgscroll` 显式声明 `overscroll-behavior-y: auto`，即允许链式滚动，切勿改成 `contain`——那会让手势被困在框内）。
  - **横向溢出兜底**：`.msgscroll` 为 `overflow-x: hidden`（避免整块对话区横向漂移），故 `.markdown-body` 设 `overflow-wrap: break-word` 让长 URL / 长 token 在 940px 列内换行而非被裁（用 `break-word` 而非 `anywhere`，以免改变 min-content 尺寸、干扰表格列宽计算）。

每条消息按角色渲染：

| 角色             | 样式                                       |
| -------------- | ---------------------------------------- |
| User           | 浅色卡片/气泡，靠右或正常展示                          |
| Assistant      | 白底，含 `thinking`（可选收起）与正文两段               |
| Tool Call      | 收起式工具条（命令行图标 + 工具名 + 参数摘要 + 状态），本期做成只读折叠条 |
| 子智能体（SubAgent） | 机器人头图标折叠块（见下），挂在所属 assistant 消息下         |

- **thinking（思考）**：来自 `thinking_delta`，折叠行以**大脑图标**标识「深度思考」（区别于工具执行条的命令行图标），点击行可展开/收起，折叠箭头（chevron）位于文本**右侧**。思考正文用**浅蓝底 max-height 自适应滚动框**（上限约 146px，即 `clamp(120px, 20vh, 146px)`：默认窗口下 146px，窗口变矮时随视口比例缩小、下限 120px；文本不足上限时按实际内容高度显示，超出时框内上下滚动）展示，不使用原生 `<details>` 元素，避免出现其自带的「Details」折叠按钮。交互节奏：`thinking_delta` 流式输出期间（`thinkingActive=true`）框**自动展开**实时显示流式思考并**自动滚到底**保证最新内容可见，标题右侧同时显示**小型转圈图标**（与工具执行条运行态同一 spinner 样式）提示模型正在思考；思考完成（开始输出正文 / 调用工具 / `turn_end`）后 `thinkingActive` 置 false，转圈图标消失且框**自动折叠**回标题行。点击标题可重新展开为同款自适应框，内容超出时框内上下滚动。历史回放消息为静态已完成态，默认折叠，不显示转圈图标。

- **子智能体执行块**：当主智能体调用 `sub_agent` 工具时，子智能体的执行过程以**折叠块**展示在其 assistant 消息下：

  - 块头部：**机器人头图标** + 任务名 + 右侧状态区（状态徽标 / 耗时 / 状态图标）+ 折叠箭头；点击头部可展开/收起。四种状态：
    **执行中**（紫色「执行中」徽标 + 脉冲转圈）、**已完成**（勾 + 耗时如 `12s`）、
    **失败**（红色「失败」徽标 + 红叉，边框着色，展开可见失败原因）、
    **已中断**（黄色「已中断」徽标 + 停止图标，表示进程被强杀、只留下启动记录）。

  - 块内容：子智能体的**思考过程**（大脑图标，可折叠）与**工具执行**（命令行图标折叠条），样式与外层一致，但整体折叠在子智能体块下；执行中且尚无产出时显示「子智能体正在准备…」占位。**子智能体返回给主智能体的答复正文不在卡片中展示**——那是给主智能体的结果，不是给用户的内容（避免与主智能体的复述重复）。

  - 数据来源：子智能体转发的 `thinking_delta` / `tool_call*` 事件（携带 `subagent_id` 标识），由前端路由进对应块；块以 `sub_agent_start` 创建、`sub_agent_end` 收尾。并行多个子智能体时按 `subagent_id` 各自成块；子智能体内部并行多个工具调用时按 `tool_id` 各自成行（不串台）。

  - **工具行的真实执行状态**：`tool_call`（流聚合完成）到达时工具**尚未执行**——参数刚拼完而已。
    卡片里工具行的"执行中 → 完成"以 `tool_exec_start` / `tool_exec_end` 事件为准（子智能体内部
    每个工具真正开始/结束执行时由后端发出，按 `tool_id` 拨回转圈 / 打勾）。缺了这对事件，工具
    执行阶段（往往最耗时，如批量读 PDF）卡片会完全冻结、工具行全部"假完成"——后台子智能体
    场景下表现为"子智能体与前端的状态断了，直到主智能体续轮输出才回来"（2026-09-12 修复）。

  - **唯一锚点规则**：卡片永远挂在**发起它的那条 assistant 消息**下——用 `sub_agent_start` 携带的 `tool_id`（发起方主工具调用 id）定位宿主消息；该 `subagent_id` 的块一旦建立，其后续事件沿用同一宿主（子智能体的 `thinking`/`tool_*` 事件不带该 id，只能靠这一条保证不被挂到别的 assistant 上）。实时与回放共用同一规则 → **切换会话前后卡片位置不跳变**（历史缺陷：实时挂在末尾新建气泡、回放挂在发起方消息，切会话时位置会跳）。

  - **持久化与回放**：子智能体执行过程持久化到**旁路文件** `session_N.subagents.jsonl`（与主 jsonl 物理隔离，见 03 篇 2.1.1），切会话/重开后由 `session_history` 的 `subagents` 字段恢复折叠块（含状态与耗时）；**但不进入主模型上下文**——主 LLM 只收到子智能体返回的摘要。启动时先落一条 `running` 占位记录，因此进程被强杀后历史里仍留有「已中断」痕迹。

  - **一致展示规则**：不管实时执行还是历史回放，`sub_agent` 永远只以折叠块（机器人头图标卡片）形式展示：

    - 实时流式：`sub_agent_start` 新建折叠块，`tool_call_start` 不渲染普通工具条（但记录锚点 id）；

    - 历史回放：前端 `historyToMessage` 把 `toolCalls` 里的 `sub_agent` 自动剥离出来转成折叠块；后端有旁路记录则用后端记录，后端缺失（老数据）则派生一张占位卡片；

  - **一致展示效果**：实时流与回放两条通道展示同一结构，回放块为已完成态（无流式光标）；无论会话完成多久、来回切换多少次，永远保持折叠卡片展示，不退化回普通工具条。

  - 后台子智能体（`run_in_background=true`）：transcript 在后台任务完成时**立即落盘到旁路文件**，切走切回就能看到完整折叠块，无需等下次用户输入；完成时主 turn 若已结束，卡片仍挂回**发起它的那条 assistant**（而非末尾新建气泡）。

  - **后台完成自动总结**：后台子智能体跑完后，主智能体会被**自动唤醒续一轮**（后端行为，见 03 篇 1.1），拿到 `<task_notification>` 结果后给出最终总结回复——不会停在"已派发后台任务，稍等片刻"的占位话术上。前端无需为这一轮做任何特殊处理：它只是一次普通的 `running` 态 turn（复用同一消息缓冲的追加逻辑），事件流照常渲染。

- **正文 Markdown 渲染**：`content_delta` 汇聚后，用轻量 markdown 渲染（代码高亮 + 代码块）。

- **消息文本可选中**：全局 `body` 设置了 `user-select: none`（防止误选 UI 元素），对消息正文重新放行 —— User 气泡（`.msg-bubble.user`）与 Assistant 正文（`.markdown-body`）均设 `user-select: text`，两角色消息文字都可用鼠标拖选。思考过程折叠块、工具条、子智能体折叠块等非正文区域保持不可选中。

- **消息右键复制菜单**：在 User 与 Assistant 的消息行（`.msg-row`）上绑定 `onContextMenu`，`preventDefault` 屏蔽浏览器原生菜单，弹出自定义 `MessageMenu`（fixed 定位于光标坐标，复用 `session-menu`/`session-menu-item` 样式类）。菜单项提供「复制」，将**该条消息的原始正文**（`msg.content` 纯文本）写入剪贴板（`navigator.clipboard.writeText`）。菜单关闭方式：点击菜单外部 / 在别处再次右键 / 按 `Esc`。靠近视口边缘时自动向内收拢，避免被裁剪。

- **消息底部元信息（时间 + 悬浮复制按钮）**：User 气泡（`.msg-bubble.user`）与 Assistant 正文（`.assistant-body`）底部右下各挂一个**元信息组**（`.msg-meta`，flex 横排），左侧是**消息记录时间**（`.msg-time`，格式 `YYYY-MM-DD HH:mm:ss`，即 jsonl `created_at` 的秒级 ISO 本地时间去掉 `T`），右侧是**悬浮「复制」按钮**（`.msg-copy-btn`，复用 `copy` 图标）。整个元信息组默认 `opacity: 0`，鼠标悬停消息行（`.msg-row:hover`）时以 `0.15s` 淡入。定位 `position: absolute`：User 与 Assistant 统一 `bottom: -26px; right: 0`（浮在消息体右下外侧）。点击按钮 `stopPropagation()` 后调用与右键菜单一致的 `copyContent()`，复制该条消息原始正文。两种复制入口并存，均写入 `msg.content` 纯文本。

  - **时间来源**：回放时来自 jsonl 行内 `created_at`（`_message_to_json_row` 落盘打点、`load_session_history` 携带、`_history_to_ui` 透传）；实时消息由前端在缓冲创建时以 `nowLocalIso()` 本地打点（与后端 `_now_iso` 同构）；老会话行无 `created_at` 时不渲染时间（与 footer 模型段同规则）。
  - **滚动边界**：`.msglist`（内容列）底部 padding 留 `calc(var(--sp-5) + var(--sp-1))`（28px），保证滚动到底时末条消息的 -26px 元信息组仍在可视区内。

- **流式光标**：生成中在末尾显示闪烁光标。

- **token 消耗 footer**：每轮对话结束（`turn_end` 后随到的 `usage_stats` 事件），在该轮末条 assistant 消息尾部显示**两段式 + 模型快照**统计小字：

  ```
  本轮 12,345 tokens · 缓存命中 87%（deepseek-flash · 128K · 思考 高）│ 本会话累计 45.6k tokens · 命中 82%
  ```

  - 第一段（本轮）：该轮全部 LLM 调用的合计（主智能体工具循环内的多次调用 + 同步子智能体），数据来自 `usage_stats.usage.turn`；
  - 第一段括号内（本轮模型快照，2026-09-16 新增）：数据来自 `usage_stats.usage.model`（`TurnModelInfo`），显示 `模型名 · 窗口标签 · 思考 档位`（档位映射与输入区悬浮面板一致：low→轻 / high→高 / very_high→极高）；思考档位空串或模型名/窗口全缺时不显示对应节，老轮次（无 model_info）整段括号不渲染；
  - 第二段（本会话累计）：turn 收尾时的会话级累计快照（`usage_stats.usage.session`），与圆圈 tooltip 同源；两段之间以细竖线分隔（`.msg-usage-sep`）；
  - 缓存命中率 = `cached_tokens / prompt_tokens`（输入侧）；provider 未返回缓存信息（`cached_tokens=0`）时显示 `缓存 —`；
  - 数字格式化：≥10000 用 `k` 缩写（如 `45.6k`，≥100k 取整），否则千位逗号；
  - **回放**：切会话后 footer 从 jsonl 轮末 assistant 行的 `usage` / `model_info` 字段恢复，但**仅第一段**（会话级快照不落盘）；
  - **边界**：迟到完成的后台子智能体不回改已定稿的 footer（只补 tooltip），其消耗计入下一轮 footer 的「本会话累计」；无消耗轮/老会话无 `usage` 字段时不渲染 footer。

- **模型切换提示（2026-09-16 新增，2026-09-16 修订）**：用户在下拉框切换模型导致**模型 id 真正变化**时，在切换发生处展示一条**居中的浅灰提示**，视觉与主流 Agent 产品一致——提示文字两侧各一条浅灰横线、文字居中、右侧带 ⓘ 信息标记、无背景填充（无顶部线）：

  ```
  ─────────── 模型已从 Deepseek-V4.1-Flash 更改为 GLM-5.3-Flash ⓘ ───────────
  ```

  - **触发范围**：仅在**模型 id 真正变化**时响应；仅调整模型参数（思考强度/更大上下文等，`model_info` 其它字段）不触发。
  - **展示时机与位置（按切换发生时是否处于 turn 执行期区分）**：
    - **空闲期切换**（turn 未执行，即上一轮答复结束后、下一条指令发送前切换下拉框）：后端**立即**上行独立 `model_switch` 事件，提示挂在**「切换时最后一条 assistant 消息」**（缓冲末尾那条已完成答复 / jsonl 末条 assistant 行）上，**先于用户下一条指令展示**，而不是等到下一轮答复末尾（2026-09-16 修订：此前空闲切换计入 pending、下一轮 run_turn 才并入并显示在「新对话答复末尾」，与「即时显示」诉求不符）。
    - **turn 执行期切换**（对话生成过程中切换）：计入本轮 `_turn_switches`，本轮收尾取净变化注入 `model_info.switch`，随 `usage_stats` 事件 `model` 上行，显示在**本轮答复末尾**。
  - **展示口径 = 净变化（轮始→轮末）**：本轮多次切换 A→B→C 时只显示「模型已从 A 更改为 C」（取首条切换的 from、末条切换的 to）；**净切回原模型**（如 A→B→A，轮末==轮始）整条提示**不显示**。空闲期连续切换同理，每次切换即时刷新该条 assistant 上的 switch 快照（从→到逐跳更新）。
  - **实时链路**：切换即由后端 `record_model_switch()` 记录——空闲期即时上行 `StreamEvent(type="model_switch", switch=sw)` 并调用 `append_switch_to_last_assistant` 持久化；turn 执行期计入 `_turn_switches`，收尾经 `_net_turn_switch()` 取净变化注入 `model_info.switch`。前端统一从 `msg.switch` 渲染提示（`.model-switch-notice`）——实时由 `model_switch` 事件 / `usage_stats.model.switch` 写入，回放由 `model_info.switch` 恢复（此前从 `msg.usage.model.switch` 读取，现统一为消息级 `switch` 字段）。
  - **回放/持久化**：切会话、重启后从 jsonl assistant 行 `model_info.switch` 恢复并重新渲染（见 07 篇持久化口径）。空闲期切换即时落盘到「切换时末条 assistant 行」的 `model_info.switch`，turn 执行期切换在收尾随 `model_info` 落盘；`load_session_history`/`_message_to_json_row` 原样保留 `model_info`（含 `switch`），切换会话后再切回，历史轮次的切换提示与 footer 模型/「本会话累计」均按磁盘数据复现。
  - **边界**：全新会话首次绑定模型（无前序模型）不视为「切换」，不记录不显示；净切回原模型（`from_id == to_id`）时 `switch` 节点不入 jsonl、前端亦跳过，前后端均无显示。

- **自动滚动跟随（贴底策略）**：消息滚动视口 `.msgscroll`（2026-09-20 起滚动职责在视口层，原为 `.msglist`）只在用户「贴底」时才自动跟随滚到最新内容，避免流式输出高频触发滚动导致画面上下跳动：

  - 贴底判定：滚动条距容器底部 `48px` 以内视为贴底；用户向上翻看超过该距离即视为脱离跟随，此后流式输出不再抢占滚动位置，可自由回看历史；

  - 用户滚回底部附近自动恢复跟随；

  - 切换会话（含首次加载/历史回放）时强制重置为贴底，回到最新消息；

  - 滚动实现直接赋值 `scrollTop`（即时吸底），不使用 `scrollIntoView({ behavior: 'smooth' })`——流式输出时每个 `content_delta` 都会刷新消息缓冲，smooth 动画被高频重复触发会叠加补偿滚动，是画面上下抖动的根源。

    - **发送可用性**：`有正文 || 有就绪附件` 且**无 staging 中的附件**且未触发图片能力拦截。**「仅附件无正文」是合法发送**（后端 `main/index.ts` 的守卫已相应放宽 —— 历史 bug 就是它把这类消息静默丢掉）。

  - `完全访问`：权限下拉（后端有权限校验能力，本期做展示/占位）

  - **工作空间选择器**（2026-09-18 接线，2026-09-20 从底部上下文行上移至权限下拉右侧）*：`📁 <当前工作空间名> ▼` 由静态占位改为**真正的工作空间切换器**（早期版本硬编码文案、无任何行为）。点开为两段式下拉：

  - `⬆`：发送按钮（紫→蓝渐变，圆角方钮）。**当前激活会话正在执行时**（`isSending`），其**变成一个可点击的** **`■ 停止`** **按钮**。点击停止当前显示会话的这一轮 turn **连同它的后台任务**，其它会话不受影响。

    - **停止态判据与侧边栏"执行中"完全一致（2026-09-21 起；此前只看 `runningSessions`，属事故，勿回退）**：
      `isSending = runningSessions.includes(activeSession) || bgSessions.includes(activeSession)`，
      即 `running`（turn 执行中）与 `background`（turn 已结束、后台任务仍在跑）**都显示停止按钮**。
      旧设计（2026-09-14）刻意让 `background` 不显示停止按钮，理由是"侧边栏点 = 还有活没干完，
      停止按钮 = 当前 turn 能不能打断"，两个判据不同。后果是用户在侧边栏看到会话亮着脉冲点、
      输入框却只有发送按钮 —— 与列表状态打架，且后台子智能体跑很久时用户**没有任何停止入口**
      （这是 `session_ru9YbrrmRD` 复现的真实体验）。
    - **配套后端改造（停止真的能停后台子智能体，否则按钮不能显示）**：`SessionRuntime.request_stop()`
      在原有 `stop_evt` + `agent.request_stop()` 之外追加 `background_manager.request_stop_all()`：
      - 每个后台任务派发时建一个独立 `stop_event`（`_execute_tool_call` 创建后同时交给 executor 与
        `start_background_task` 登记）；`sub_agent` 的 executor 把事件透传给 `spawn_subagent`，
        子智能体在**每轮 LLM 调用前**与**每次工具执行前**检查，命中即收束为 **`status=aborted`**
        的 transcript（前端卡片显示「已中断」徽标，已产生的轮次仍可回放）；
      - 任务状态立刻置 `stopped` → `has_running()` 转 False → `_watch_background` 退出（且已置位的
        `stop_evt` 让它**不再自动续轮**，被放弃的结果不会再注入）；
      - worker 迟到完成时**不得把 `stopped` 复活成 `completed`**（否则停了还会续轮注入结果）；
      - 不支持中断的后台任务（如 bash 跑长命令）线程会跑完当前调用，但状态已是 `stopped`，结果丢弃。
      - 同步路径的 `sub_agent` 也接管停止：`_make_executor` 传主智能体自身的 `_stop_evt`，长时间
        执行的同步子智能体同样在迭代边界停下。
    - 由于停止后进 `# stop` 分支不再续轮，`background` 态点停止会丢失"自动续轮的那条最终总结"——
      这是**用户主动放弃**的语义，可接受；session 止步于 `done` 而非 `stopped`。

### 3.4 任务面板（输入框上方，2026-09-16 新增）

**位置**：`.chat` 内、`MessageList` 与 `.composer-wrap` 之间 —— 即"固定在对话框（输入框）上方"。
**组件**：`components/Chat/TaskBoard.tsx`；样式为 `chat.css` 的 `.task-card*` 系列。

**出现条件**：当前会话存在**未完成任务组**才渲染。没有活时面板完全不存在，不占位。

| 部分 | 说明 |
| --- | --- |
| 表头（40px，整行可点击折叠） | 折叠箭头 + `任务进度` + `已完成/总数` + 状态徽标（**三态**：执行中脉冲 / 待继续 / 全部完成）+ 等待依赖计数 |
| 进度条（2px） | 完成比例；全部完成后转为绿色 |
| 列表（固定 **168px**，超出纵向滚动） | 每行：状态点 + 缩进（按 `depth`，每级 14px）+ 标题 + 子项进度 + 依赖计数 + 认领者 chip + 完成摘要 |

**四种状态点**：`pending` 空心圆 / `in_progress` 实心紫 + 脉冲 / `blocked` 红色虚线框
（**派生态**：依赖未完成）/ `completed` 实心绿 + 标题删除线。

**状态徽标是「三态」，判据不是 `board.status`（2026-09-18 修正）**：

| 徽标 | 判据 | 含义 |
| --- | --- | --- |
| 执行中（紫色 + 脉冲） | `board.has_in_progress` | 组内**确有一条 in_progress**，真有东西在跑 |
| 待继续（灰色，无脉冲） | 未完成 且 `!has_in_progress` | **有活但没人跑**：残留未认领项 / 依赖卡住 |
| 全部完成（绿勾） | `board.status === 'done'` | 组内全部 completed |

> `board.status === 'running'` 只说明"这组活没干完"，说明不了"现在有人在跑"：
> 一条没人认领的 pending/blocked 残留会让它长期停在 `running`。
> 早期版本直接拿它渲染「执行中」，于是出现**会话早已完成、面板却说执行中**的假象
> （真实事故见 10 篇第 17 节）。`has_in_progress` 由后端 `build_board` 派生（不落盘）。

**关闭语义（需求的硬约束，2026-09-18 放宽一格）**：

| 组状态 | 收起 / 展开 | 关闭 |
| --- | --- | --- |
| 执行中（有 `in_progress`） | ✅ | ❌ **不渲染任何关闭入口**（"执行完之前不能关闭"） |
| 待继续（有活但没人跑） | ✅ | ✅ 显示「关闭」—— 停滞 ≠ 在执行，锁着入口只会把用户困住 |
| `done` | ✅（自动收起） | ✅ 显示「关闭」，点击后本地忽略该组 |

> 「停滞可关闭」是**逃生阀**：万一后端仍留下清不掉的残留项，用户至少能收起/
> 关掉面板，而不是被永久钉在"执行中"上。注意与「续跑」解耦 —— 关闭只是本地忽略
> 该组（换组后重新出现），不发任何指令，续跑依旧靠输入框手打消息。

折叠状态**按 `group_id` 记忆**：快照是整份替换、且任务每次状态变化都会重推，
不按组重置的话用户手动展开/收起会被反复打断。

**续跑入口：没有按钮，靠输入框手动发消息**（2026-09-16 拍板，原「继续执行」按钮已删除）。

原先表头右侧有一个「继续执行」按钮，判据是「有活 + 现在没人在跑」：

```
board.status === 'running' && !runningSessions.includes(sid) && !bgSessions.includes(sid)
```

删除原因有两个：

1. **功能冗余**：续跑所需的两个后端机制都在 `Agent.run_turn()` 内部 ——
   `_sync_task_board()` 的尾部注入（存在未完成组且历史里没有该 `group_id` 的注入时补注）
   与 `release_stale_in_progress()` 的 `in_progress → pending` 归一，二者都**与"这一轮由谁触发"无关**。
   因此用户直接在输入框发一条「请继续」与点按钮走的是同一条通路（都是 `send()` → `run_turn()`），
   实测完全等效。
2. **渲染故障**：按钮复用了侧边栏的 `.mini-btn`（固定 `24×24` 的纯图标按钮），
   塞进「继续执行」4 个汉字后被压成每行一个字、竖直溢出面板外 —— 即用户看到的"跑位"。

> 这个判据本身的设计取向（**不检测"是否发生过中断"**）仍然有效，只是不再有 UI 承载：
> ① 前端切换会话并不会中断会话（每个会话有独立的运行时），用中断做判据没有依据；
> ② 会落到"有活 + 没人在跑"的有三种情况 —— 用户点了停止、进程被杀、
> **模型自己收尾时留了尾巴**（规划 7 项只做完 3 项就结束了本轮）。第三种比"被中断"更常见。
> 若将来要恢复按钮，必须另起一个自适应宽度 + `white-space: nowrap` 的类，不要复用 `.mini-btn`。

### 3.5 待确认选项面板 + 只读小结块（`ask_user`，2026-09-21）

完整设计见 **Doc16**，这里只记界面。

模型可以**在同一个回合内**向用户提问并等答案（`ask_user` 工具，阻塞式）。
UI 分两块，**位置刻意不同、视觉刻意不同**：

| | 待确认面板 | 只读小结块 |
| --- | --- | --- |
| 位置 | 输入框位置（`TaskBoard` 之下；**出现时输入区整块让位**） | 发起提问的**那条 assistant 消息里**，插在正文当中 |
| 组件 | `AskUserPanel.tsx` / `.ask-panel*` | `AskUserBlock.tsx` / `.ask-block*` |
| 时机 | 有**在途**提问时出现，结算即消失 | 结算后**留下**，是历史凭证 |
| 视觉 | 紫调描边 + 紫调表头（"需要你做个决定"） | 中性浅灰底 + 左侧结局色条（"已经过去的事"） |
| 可交互 | ✅ 选项 / 自定义 / 上一步下一步 / 取消 | ❌ 只读（可折叠），正文原样展示 |

**面板**（一题一屏，`第 N/M 题`）：

| 部分 | 内容 |
| --- | --- |
| 表头（38px 紫调底） | 图标 + `需要你确认` + `第 N/M 题` + `可多选` 提示 + 「取消」 |
| 步骤条 | 每题一个可点击胶囊（序号 → 答过变对勾 + `header`），**可任意跳题** |
| 题目区（≤260px 滚动） | `header` 小标 + 完整问句 + 选项列表 + 「其他」行（若 `allow_custom`）+ 自定义输入框 |
| 底部 | 「逐题选择后提交；要自己写答案请选「其他」」提示 + 「上一步」+ 「下一步」/「提交」 |

- **单选＝圆点、多选＝方框**：形状本身告诉用户能不能多选，不必读文字提示。
- **不强制作答**：允许空提交（后端渲染「（未选择）」）——强行要求选择只会逼用户编答案。
- **单选可反选**：再点一次已选项 = 取消选择（点错了不必取消整个提问）。
- **Enter = 下一步 / 提交**（只在焦点位于面板内时触发）。
- **等待期输入区整块让位**（2026-09-22 改，见 Doc16 §5.2）：面板一出现，`.composer-wrap`
  就隐藏（`.chat--asking`），作答期间只能选选项 / 写「其他」/ 取消。
  两条作答路径并存会让人"输入框里打一半又去点选项"，两边都像已经答了；
  输入区里的草稿**不丢**（编辑器不卸载，只是被 CSS 隐藏 —— 它非受控）。
  副作用：输入区同时是「停止」按钮所在地，让位期间要停只能先「取消」再「停止」。
- **提交后不本地关面板**：等 `ask_resolved` 关闭（后端对重复提交是幂等丢弃，
  乐观关闭会在"作答被丢掉"时造成假象）；提交按钮 3s 自动解锁，避免点不动。

**只读小结块**：徽标四态 `✓ 已确认选项` / `× 已取消提问` / `■ 提问已中断` / `🕐 提问未完成`
（最后一种 = 回放发现 `result` 为空，如进程被杀）。正文是后端生成的 `result_text`，
**前端不做任何解析**、`white-space: pre-wrap` 原样展示 —— 实时与回放因此必然一致。
`status === 'pending'`（在途）时**不渲染**，此刻由面板承载。

**小结块在正文里的落点**（2026-09-22 改，见 Doc16 §5.4）：插在**发起提问那一刻**
的正文位置 —— "先跟你确认几个关键项，确认完我再出完整攻略"这句在卡片**上方**，
提问后（同轮）续写的正文在卡片**下方**。切分点由实时路径在 `tool_call_start`
记下的 `contentOffset` 提供；回放缺省视作"正文全在卡片之前"（jsonl 每次 LLM
调用一行，正文必在提问之前），两条路径结果一致。

> `ask_user` 的调用**不进普通工具条**（与 `sub_agent` 同一条纪律），
> 否则工具条、面板、小结块会三处重复表达同一件事。

### 样式规范要点

- 扁平、圆角（`--radius-md`）、细边框（`--color-border`）、弱阴影。

- 主行动按钮用 `--color-action-grad` 渐变；普通按钮灰底。

- 侧边栏 `--color-bg-sidebar`，主区 `--color-bg-main`，分隔用 `--color-border`。

- macOS 风格：顶部是 **40px 自绘标题栏**（`--titlebar-height`），无额外重边框；
  栏内只有"应用名（居中）+ 右栏开关"，其余一律不放，避免变成第二条工具栏。
  **拖拽区是 `.titlebar-drag` 填充块，不是整条栏** —— 不变式：没有任何
  `-webkit-app-region: drag` 矩形与栏内可点元素相交（否则点击会被当成拖窗吞掉）。

- **带圆角边框的容器，其内部可输入元素必须显式透明背景**（2026-09-20 修复）：`textarea` / `input` 的 UA 默认底色是白色（`background-color: field`），而**子元素绘制在父级边框之上**——它会盖掉父级 `border-radius` 的圆角与相邻边框线。输入区 `.composer` 的左上/右上角曾因此变成方角、顶边线断开（现象：只看到两条直边、看不到圆弧）。修法：`.composer-input { background: transparent }`，白底与圆角统一由 `.composer` 画。新增同类结构（圆角容器 + 原生输入元素）时要一并处理，别只调 `border-radius`。

### 全局 Toast 规范

- 组件：`@components/common/Toast`，挂载于 `App`，数据源 `agentStore.toast / toastType`。

- 位置：**窗口顶部居中**（`position: fixed; top: var(--sp-4); left: 50%`），深色底白字，error 态换 `--color-danger` 底色。

- 自动消失：**所有 toast 都必须自动消失**，统一走 `agentStore.ts` 导出的 `showToast(msg, type, ms)`（info 默认 3000ms，error 默认 4000ms）；模块级计时器在重复触发时重置，避免旧计时器提前清掉新提示。禁止直接 `setState({ toast })` 绕过计时器（会复现「提示永不消失」的 bug）。

- 触发来源：保存模型配置结果（`saveLlConfig`）、后端 `llm_config` / `error` 事件、侧边栏快捷操作占位提示（`QuickActions` 自动化项）。

### 7.1 结构

```
┌─ 自绘标题栏 .titlebar (40px，满宽；拖拽区 = 三块 .titlebar-drag 填充块) ──┐

├───────────┬──────────────────┬──────────────────────────────┤

│  侧边栏    │     聊天区        │ │[文件][tools.py][*App.tsx*][变更] [+]│ ← 「+」钉在栏尾
│  240px    │                  │ ├─────────────────────────┤  │
│ (灰)      │                  │ │     当前标签的正文        │  │
│           │                  │ │  (树 / 预览 / 变更 / 欢迎) │  │

> 标题栏那枚图标**只管开合取反**（`togglePanelOpen`，读 store 当前值取反 → 点开、再点关；
> **不在组件里写 `!渲染时的布尔`**，那会退化成"点得开、点不关"）；开哪个视图在栏内选
> （「+」菜单 / 欢迎态四入口），键盘直达走 `⌘⇧E`（文件）/ `⌘⇧G`（变更）。
> 2026-09-23 前这里是并排两枚带字按钮（`文件` / `变更`），已收敛；同日它从
> 聊天区顶栏上移到窗口最外层（`.chat-toolbar` 随之删除）—— 理由见 19 篇 §3.3。
> 标题栏底色的**左灰右白**与下面三栏对齐：左侧 240px 用 `--sidebar-width` 画灰底
> （交通灯落在这里），其余用主区白底。

### 7.2 三种标签身份（一眼可辨）

| 身份 | 视觉 | 来源 |
| --- | --- | --- |
| **视图标签** | 图标 + 名称（`文件`/`变更`/`终端`/`浏览器`） | 「+」菜单 / 欢迎页 / `⌘⇧E`·`⌘⇧G` |
| **常驻位文件** | 正体文件名，`title` = 绝对路径 | 树里点文件 / 变更行尾「在右栏打开」 |
| **预览位文件** | **斜体** + 前置来源圆点，`title` = `来自会话链接 · <绝对路径>` | **会话内点文件链接** |

预览位**全场唯一**：再点别的文件**就地顶替**（不新增、不移动位置）；双击它可升级为常驻位。

### 7.3 三条硬交互

1. **右栏按会话隔离**：切会话换一整套标签，切回逐项复原（含激活项）。
2. **「再点一次 = 收栏」不是"关标签"**：标题栏图标（纯开合）与 `⌘⇧E`/`⌘⇧G`（视图直达，
   已在看该视图时再按即收栏）管"这一栏要不要占屏幕"，标签是"我打开过什么"的持久记录
   —— 关光标签右栏仍在（回欢迎态）。
3. **Esc 分层**：有「+」菜单时只关菜单，再按才收栏；输入框/`contentEditable` 聚焦时不响应。
