# 设置与模型管理

> 本文档描述桌面智能体客户端的**设置弹窗** 与**大模型配置管理**（含热切换）。核心结论：设置从右侧抽屉改为**应用居中弹窗、左侧菜单（通用/模型/关于）**；大模型配置独立存放于 `~/.aigent/llmconfig.json`（从非敏感 `config.json` 分离，含 api\_key 权限 0600），支持多服务商多模型，保存即**进程内热切换生效，无需重启**。按「概念 → 设计 → 落地」组织。

## 一、概念

### 1. 为什么设置改成居中弹窗

TraeWork 的设置有「应用级全局设置」和「工作区快捷面板」两层。此前我们用右侧抽屉（Drawer）同时承载目标/待办/技能/设置四个面板，语义混杂；且抽屉是「贴边浮层」而非「独立设置中心」。

整改目标：设置是**独立的应用级对话框**，与当前对话无关，应居中弹出、模态阻塞，左侧为菜单栏。本期仅保留 **通用 / 模型 / 关于** 三个菜单；其它原抽屉里的目标/待办/技能面板不再作为设置入口（相关后端能力保留，后续如需再以独立面板接入）。

### 2. 为什么大模型配置单独用 `llmconfig.json`

- **属性不同**：`config.json` 是「非敏感、扁平键」的运行时参数（超时、token 上限、压缩阈值等），而大模型配置是**结构化、含密钥**的实体（服务商 + 模型 + api\_key + 端点）。硬塞进 `config.json` 会污染它的扁平键语义。

- **密钥隔离**：`llmconfig.json` 含 api\_key，权限定为 `0600`，与 `credentials.json` 同级对待。但它比 `credentials.json` 更结构化（需要表达多个服务商、多个模型、启用状态），所以单独成文件，而不是复用扁平密钥文件。

- **多服务商扩展**：本期仅 DeepSeek 与硅基流动，未来加服务商只增预置数据，不改结构。

### 3. 为什么「保存即生效」而不用重启

用户添加一个模型就重启程序是不可接受的；重启只应发生在**程序版本升级**时。因此采用**进程内的运行时重绑定**：大模型运行时本质是一组「该向谁、用什么 key、用哪个模型 id 发请求」的绑定，这些绑定全部持有在进程内对象上，可以就地更新，无需重建进程。

## 二、设计

### 1. 设置弹窗 UI 结构

```
┌───────────────────────────────────────────┐
│  设置  (左栏 180px)    模型            [×]   │
│  ┌──────────┐  ┌─────────────────────────┐ │

│  │ 关于      │  │ │模型    │服务商  │操作│ │ │
│  │          │  │ ├───────┼────────┼───┤ │ │
│  │          │  │ │DeepSeek-V4│…  │编辑  │ │ │
```

- 外框：半透明遮罩 + 居中弹窗（720×520，可缩放上限），顶部右侧关闭按钮，点遮罩关闭。

- 左栏：`通用 / 模型 / 关于` 三个菜单项；`模型` 为默认打开页。

- 右内容区：按当前菜单渲染；`通用` / `关于` 本期为占位页。

### 2. 「添加模型」流程（参考 Trae）

点击 `+ 添加模型` → 弹出二级弹窗：

1. **选服务商**：网格按钮（DeepSeek / 硅基流动），选中即预填该服务商 `base_url` 与候选模型。
2. **填表单**：

   - 服务商（必填，网格单选）

   - 模型（必填）：`datalist` 输入框，可点候选 chip 或自由输入自定义模型 id

   - 显示名称（可选，留空沿用模型 id）

   - API 密钥（必填，带明文切换「小眼睛」，附「获取 API 密钥」外链）

   - 接口地址（默认取服务商端点，可改）

   - 启用模型（开关，默认启用）
3. **保存**：走 `llm_config_save` → 写入文件 → 热切换 → 列表更新。

**编辑 / 删除 / 启用**：

- 编辑弹窗复用同一表单；**API 密钥留空 = 沿用原密钥**（密钥不回显，避免泄露）。

- 删除：至少保留一个模型（后端约束），最后一个模型不允许删。

- 启用开关：即时持久化并热切换。

### 3. `llmconfig.json` 结构

```json
{
  "active_model_id": "deepseek-chat",
  "models": [
    {
      "id": "deepseek-chat",
      "provider": "deepseek",
      "display_name": "DeepSeek-V4-Flash",
      "model": "deepseek-chat",
      "base_url": "https://api.deepseek.com",
      "api_key": "sk-xxx",
      "enabled": true
    }
  ]
}
```

- `active_model_id`：激活主模型；为空时取第一个启用的模型。

- `models[]`：模型配置列表，支持多服务商混排。

- 运行态主/备模型推导：主 = 启用的 `active_model_id`（或首个启用），备 = 另一个启用的模型。

**预置服务商数据**（本期）：

| 服务商 key       | 名称       | base\_url                       | 候选模型例                              |
| ------------- | -------- | ------------------------------- | ---------------------------------- |
| `deepseek`    | DeepSeek | `https://api.deepseek.com`      | deepseek-chat / deepseek-reasoner  |
| `siliconflow` | 硅基流动     | `https://api.siliconflow.cn/v1` | DeepSeek-V3 / DeepSeek-R1 / Qwen 系 |

预置数据仅作候选，允许用户自定义模型 id 与端点。

### 4. 热切换架构（进程内重绑定）

运行时用到的 LLM 绑定共 **6 处**，全部在 Agent 实例内部：

| 绑定        | 持有对象                                 | 热切换方式                |
| --------- | ------------------------------------ | -------------------- |
| 自身主/备模型   | `self.model` / `self.fallback_model` | 重读 env 赋值            |
| 主 LLM 客户端 | `self.llm_client`                    | `LLMClient().llm` 重建 |
| 错误恢复      | `self.recovery`                      | 重建                   |
| 工作流子智能体   | `workflow_manager`                   | `set_llm()`          |
| 目标评估器     | `goal_controller`                    | `set_llm()`（不丢目标状态）  |
| 子智能体      | `subagent_runner`                    | `set_llm()`          |
| 队友协作      | `teammate_manager`                   | `set_llm()`          |

流程：

```
前端保存 → ws llm_config_save
  → save_config() 落盘（0600）
  → load_llm_config()  映射进 env
  → Agent.reload_llm_bindings()  就地重建 6 处绑定
  → 立即生效，无需重启
```

### 1. 对话区模型下拉实时同步

输入区（`components/Chat/InputBox.tsx`）右下角的模型选择器已从占位按钮升级为**真实下拉**：

- **数据源**：直接读 `agentStore.llmConfig`，枚举其中的**已启用**模型；当前激活项与后端 `apply_to_env` 的 primary 推导一致（`active_model_id` 启用 → 否则首个启用模型）。

- **实时同步**：在设置弹窗里增删/启停/设置激活模型，`llm_config` 事件回写 store 的 `llmConfig`，下拉即时刷新。

- **切换即热生效**：从下拉选择某个模型 → `agentStore.setActiveModel(id)` → `saveLlConfig({ active_model_id: id, models })` → 走既有热切换链路 → 本次会话后续请求即用新模型，无需重启。

- **启动即知**：`App.tsx` 监听 `connection === 'connected'` 后调用一次 `loadLlConfig()`，保证应用启动后下拉即可反映已保存配置。

- 未配置任何模型时按钮禁用，文案显示「未配置模型」，引导去设置。

## 三、落地

### 后端新增模块 `agents/llm_config.py`

- 常量 `LLM_CONFIG_FILE = AIGENT_HOME/"llmconfig.json"`（单向 import `config` 的 `AIGENT_HOME`，`config.py` 不反import — 避免循环依赖）。

- `PROVIDERS`：预置服务商（deepseek / siliconflow）。

- `get_config()`：读文件 + 附 `providers` 预置数据下发前端。

- `save_config(data)`：规范化并写盘（`0600`），至少保留一个模型，非法抛 `ValueError`。

- `apply_to_env(data)`：把主/备模型映射为 `OPENAI_API_KEY/BASE_URL/MODEL_ID/FALLBACK_MODEL_ID`。**直接赋值**（显式模型配置是权威来源）；密钥为空时**不覆盖**现有 env key，避免运行期被空串清空。

- `load_llm_config()`：文件存在才加载映射，缺失不加载（不破坏原有 `config.json/credentials.json/.env` 兜底）。

### 启动挂载

- `agents/agent_cli.py` `main()`：`load_config()` 后再 `load_llm_config()`。

- `agents/ws_bridge.py` 模块顶部：`load_config()` 后再 `load_llm_config()`，早于 `Agent(...)` 实例化。

- 注意：`agent_full_v2` import 期 `load_dotenv(override=True)` 会把 `.env` 覆盖进 env；`apply_to_env` 用直接赋值因此仍能胜出。

### Agent 热切换接口（`agents/agent_full_v2.py`）

- 新增 `Agent.reload_llm_bindings()`：重读 env 后重建 `self.llm_client`、`self.model`、`self.fallback_model`、`self.recovery`，并对 `workflow_manager` / `goal_controller` / `subagent_runner` / `teammate_manager` 调各自的 `set_llm(llm_client, model)`。无 api\_key 时返回 `{applied: False}` 且不改动既有客户端。

- 各协作对象新增轻量 `set_llm()`：`subagent.py`、`workflow.py`、`goal.py`(GoalController)、`teammate_manager.py`。

### 后端 WS 命令（`agents/ws_bridge.py`）

| kind              | 说明                                                                           |
| ----------------- | ---------------------------------------------------------------------------- |
| `llm_config_get`  | 返回 `{kind:'llm_config', payload:{config}}`（含 providers）                      |
| `llm_config_save` | 接收 `payload.config`，落盘 → 重映射 → 热切换 → 返回 `{config, applied, msg}`；异常回 `error` |

### 前端

- 协议 `agentProtocol.ts`：新增 `ControlKind` 两枚、`UiEvent` 的 `llm_config` 类型、`LlmConfig/LlmModel/LlmProvider/LlmConfigResult` 类型。

- IPC：`preload/index.ts` 暴露 `llmConfigGet / llmConfigSave`；`main/index.ts` 注册 `agent:llmConfigGet / agent:llmConfigSave`（`request` 支持 outKind≠matchKind 与非空 payload）。

- 状态 `agentStore.ts`：移除抽屉态（`activePanel/panelText/openPanel`），新增 `settingsOpen/settingsTab`、`llmConfig/llmSaving` 与 `openSettings/closeSettings/loadLlConfig/saveLlConfig`。

- 组件：

  - 删除 `SettingsPanel.tsx`（抽屉）与 `styles/drawer.css`。

  - 新增 `SettingsModal.tsx`（居中弹窗外壳，含左侧菜单与通用/关于内联占位）+ `Settings/ModelSettings.tsx`（模型列表 + 添加/编辑表单）。

  - `UserCard.tsx` 齿轮改调 `openSettings('model')`；`App.tsx` 渲染 `SettingsModal`。

  - 新增 `styles/settings.css`。

- 样式走 `styles/tokens.css` 设计令牌（主色紫渐变、圆角、间距、阴影），无引入图标库，图标在 `components/common/Icon.tsx` 扩充（trash/close/eye/eyeSlash）。

### 关键取舍

- **模型数据与密钥同文件**：为表达结构化多模型暂放 `llmconfig.json`（0600）。未来如需更高隔离可把 `api_key` 抽出到钥匙串，结构不变。

- **编辑不回显 api\_key，留空沿用**：避免敏感信息暴露在前端内存/渲染层。

- **删除最后一条模型被禁止**：后端 `save_config` 强约束至少一个模型，保证 `reload_llm_bindings` 不会落入无主模型态。

- **`apply_to_env`** **空密钥不覆盖 env**：防止用户配置了空 key 时把已在用的 key 清空导致疑难的运行期失效。

## 四、验证

1. 后端单测：临时替换 `LLM_CONFIG_FILE`，验证 `save→load→apply_to_env` 的 primary/fallback 推导、0600 权限、缺文件不加载。
2. 端到端（`frontend` 下 `npm run dev`）：点齿轮 → 居中弹窗出现、左栏`通用/模型/关于` → 模型页列表（空态）→ `+ 添加模型` → 选 DeepSeek → 填 key → 保存 → 列表出现新模型 → 在下一轮对话可见已用新模型（无需重启）。
3. 热切换回归：改成一个已存在效 key 的模型 → 保存 → toast「已生效」→ 对话正常走新模型；停用当前主模型 → primary 自动落到下一个启用模型。
4. 缺文件场景：删除 `~/.aigent/llmconfig.json` 后重启，后端照常走原有兜底配置。
