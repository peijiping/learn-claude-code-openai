# 设置与模型管理

> 本文档描述桌面智能体客户端的**设置弹窗** 与**大模型配置管理**（含热切换）。核心结论：设置是**应用居中弹窗、左侧菜单（通用/模型/回收站/关于）**；大模型配置独立存放于 `~/.aigent/llmconfig.json`（从非敏感 `config.json` 分离，含 api\_key 权限 0600），**v2 起以「连接（模型服务/供应商）」为中心组织**（连接 → 模型 两级），支持多服务商多模型、**远端模型列表刷新**、**自定义供应商**与**自定义模型 ID**，保存即**进程内热切换生效，无需重启**。厂商公共元数据外置到 `~/.aigent/providers.json`，可随官方上新整体更新。按「概念 → 设计 → 落地」组织。

## 一、概念

### 1. 为什么设置改成居中弹窗

TraeWork 的设置有「应用级全局设置」和「工作区快捷面板」两层。此前我们用右侧抽屉（Drawer）同时承载目标/待办/技能/设置四个面板，语义混杂；且抽屉是「贴边浮层」而非「独立设置中心」。

整改目标：设置是**独立的应用级对话框**，与当前对话无关，应居中弹出、模态阻塞，左侧为菜单栏。本期仅保留 **通用 / 模型 / 回收站 / 关于** 四个菜单；其它原抽屉里的目标/待办/技能面板不再作为设置入口（相关后端能力保留，后续如需再以独立面板接入）。

### 2. 为什么大模型配置单独用 `llmconfig.json`

- **属性不同**：`config.json` 是「非敏感、扁平键」的运行时参数（超时、token 上限、压缩阈值等），而大模型配置是**结构化、含密钥**的实体。硬塞进 `config.json` 会污染它的扁平键语义。

- **密钥隔离**：`llmconfig.json` 含 api\_key，权限定为 `0600`，与 `credentials.json` 同级对待。但它比 `credentials.json` 更结构化（需要表达多个连接、多个模型、启用状态、能力声明），所以单独成文件。

- **厂商层需要独立生命周期**：连接（端点 + 密钥 + API 格式）与模型（ID + 参数 + 能力）是**两级生命周期**——端点/密钥属于账号级，模型属于该账号下可增删的条目。v1 把 `base_url`/`api_key` 冗余在每个模型上，导致「改一次密钥要改 N 条、加一个厂商无处安放」，v2 引入连接层解决。

### 3. 为什么「保存即生效」而不用重启

用户添加一个模型就重启程序是不可接受的；重启只应发生在**程序版本升级**时。因此采用**进程内的运行时重绑定**：大模型运行时本质是一组「该向谁、用什么 key、用哪个模型 id 发请求」的绑定，这些绑定全部持有在进程内对象上，可以就地更新，无需重建进程。

### 2. 模型管理页（master-detail）

模型页从「单张扁平表格」重构为**左连接列表 + 右连接详情**（对齐 Reasonix 的模型维护界面）：

**左栏（`.msvc-*`）**

- 「搜索已添加连接」输入框，按连接名过滤。
- 连接条目：头像（厂商首字母）+ 名称 + 右侧状态点（**已设密钥=绿点 / 未设=灰点**，`title` 提示）。
- 底部固定「+ 添加模型服务」按钮（打开添加供应商弹窗）。
- 无连接时显示引导空态。

**右栏（连接详情）**

- 头部：连接名（可点铅笔就地重命名）+ 密钥状态 chip（`已设置密钥` / `未设置密钥`）+ 右侧「复制此模型服务」与「⋯」菜单（复制 / 删除此模型服务）。删除连接时，若其下有当前激活模型，一并清空 `active_model_id`。
- 字段：`API 地址`（提示「填写完整请求地址：系统将原样使用」，后端落盘时自动裁掉 `/chat/completions` 等路径段得到 SDK 需要的 base\_url）、`API 格式`（下拉，来自后端 `api_formats`）、`API Key`（密文 + 小眼睛切换）。
- 分隔线 → **模型列表**（见下）。
- 「兼容设置（通常不用改）」折叠区：`模型列表接口`（默认 `/models`，即「刷新」时请求 `{API 地址}{此路径}`；个别中转服务路径不同时可改）。落进连接的 `compat.models_path`。
- 底部固定操作栏：左侧「未保存更改 / 无未保存更改」状态文案，右侧 `取消` / `保存更改`。

**模型列表编辑区（`.mlist-*`）**

行结构：`[勾选] 模型名 [当前] [已停用] [图片能力/图片能力未识别] [标签 1M] [⚙ 参数]`。

- 表头：「模型列表」+「已选择 N 个」+ 右侧 `⟳ 刷新` / `添加模型` / `⋯`（全选 / 取消全选）。
- **勾选 = 启用（`enabled`）**，即时体现在 `apply_to_env` 的可用模型集合里；
- **点模型名 = 设为「当前」使用模型**（全局 `active_model_id`，行上打「当前」标签）；输入区模型下拉的高亮与此一致；
- 行尾 `⚙` 打开「模型参数」弹窗，可改参数/能力/启用状态，也可删除该模型；
- 「预览」按钮（`⟳`）即**刷新模型列表**：经后端调 `GET {base_url}{models_path}` 拉回该账号下可用模型 id，**已存在的保留、新 id 追加**（默认未勾选），并 toast 提示「已加载 N 个模型，新增 M 个」。这是本期的核心诉求：**厂商更新模型后不必等客户端发版**；
- 自定义厂商（非预置目录）的模型不做「能力未识别」提示（无对照目录，标记无意义）。

**编辑与保存语义**

- 所有改动先落**草稿**（`draft: LlmConnection[]`），只有「保存更改」才写盘 → 热切换；「取消」回滚为当前生效配置。
- 「保存更改」按钮在无更改时禁用，避免无谓落盘与热切换。

### 3. 「添加模型服务（供应商）」流程

点击左栏「+ 添加模型服务」→ 弹出二级弹窗（`.addprovider`，900×620），顶部两个 tab：

**tab 1：推荐预设**

- 左侧：搜索框 + 服务商列表（**本期仅 DeepSeek 与 硅基流动**，来自 `~/.aigent/providers.json`）；选中项高亮。
- 右侧：厂商名（标题）→ `API 格式`（下拉）→ `Base URL`（可改，提示「可修改，仅用于当前连接，不影响预设默认值」）→ `API Key`（密文，占位文案 `设置 {api_key_env}（全局保存）`，附「密钥仅保存在本地 `~/.aigent/llmconfig.json`」）→ **模型列表**（预置候选，可刷新/添加模型）→「兼容设置」折叠区 → `添加供应商` 按钮。
- 提交时以预置目录的候选模型生成连接的初始模型列表（全部启用）。

**tab 2：自定义供应商**

- `自定义供应商名称`（如 `my-proxy`）、`API 地址`（可填完整请求地址）、`API 格式`、`API Key`。
- `模型列表`（默认空，可 `⟳ 刷新` 从远端拉、或 `添加模型` 手填）。
- 「兼容设置（通常不用改）」折叠区（模型列表接口）。
- 底部：`未保存更改 / 已选择 N 个` + `取消` / `保存更改`。

自定义厂商的 `provider` 记为 **`custom:<slug>`**（slug 由名称派生），不污染预置目录；`custom: true` 标记便于 UI 区分。新增连接后自动选中它；若全局尚无激活模型，取该连接首个模型为当前。

### 4. 「添加模型 / 模型参数」流程

模型列表的「添加模型」按钮 → 弹窗（`.addmodel`，对应 Reasonix「添加模型」）：

- **模型 ID**（必填，**自由输入**；提示「可自由输入任意模型 ID——厂商更新模型后直接填新 ID 即可，无需等待预置目录更新」）。
- **参数**（左列，与右列之间有竖分隔线）：
  - `上下文（tokens）`：下拉「继承 / 131,072 / 262,144 / 524,288 / 1,048,576 / 2,097,152」，带 `⟳` 恢复继承；下方提示「继承 · 1,048,576」（继承值来自预置元数据 `max_context_extended || max_context`）。
  - `输出上限（Token）`：下拉「继承 / 4,096 / 16,384 / 32,768 / 65,536」，提示「留空继承（…）；-1 表示不发送可选输出限制，仍受模型实际限制」。
  - `显示名称`（留空沿用模型 ID）。
- **模型能力**（右列）：
  - `输入`：文本 / 图片 / 视频 / PDF 四个可勾选 chip（输入侧至少保留一项）；提示「暂不支持直接输入视频或 PDF」。
  - `输出`：文本 chip。
  - `来源`：展示 `自动识别` / `手动覆盖`；`恢复自动识别` 按钮在手动态可点，一键回填预置能力与继承窗口。
  - 提示「仅覆盖能力声明，不会改变模型的实际上下文与参数行为」。
- **进阶参数**（折叠）：工具调用轮数 / 思考模式 / 采样参数（Temperature、Top P、Top K）——即 v1 的「高级配置」，收纳至此，任一项填写才落盘到该模型的 `advanced`；数值型字段带范围校验，非法值禁止提交。
- 底部：编辑态左侧有 `删除模型`（二次确认变红「确认删除？」）；右侧 `保存连接后生效` + `取消` + `添加到列表` / `保存`。

**自动识别**：模型 ID 命中预置目录时，能力声明与继承窗口自动回填（`capability_source: "auto"`）；一旦用户手动勾选能力即转为 `"manual"`，此后不再被自动覆盖。

### 5. 「刷新模型列表」实现

```
前端点 ⟳ → window.agent.llmModelsFetch({base_url, api_key, connection_id, api_format, models_path})
  → IPC 'agent:llmModelsFetch'（超时 30s）→ WS 'llm_models_fetch'
  → 后端 fetch_remote_models()：GET {normalize_base_url(base_url)}{models_path}
      Header: Authorization: Bearer <api_key>
  → 解析 data[].id（兼容顶层数组 / id|model|name 字段）
  → WS 'llm_models' {ok, models:[{id}], base_url?, error?}
  → 前端合并进草稿（已存在保留、新 id 追加且默认未勾选）
```

- **密钥缺省回退**：`api_key` 留空时，后端按 `connection_id` 从已存配置取回该连接的密钥（用户改完地址直接点刷新、未重填密钥的场景）。
- **Base URL 归一**：用户可能填完整请求地址（`…/chat/completions`），后端 `normalize_base_url()` 统一裁掉 `/chat/completions`、`/responses`、`/models` 等路径段后再拼 `models_path`。
- **错误可见**：HTTP 错误码与响应体片段（截断 200 字）回前端 toast（如 401 密钥错误、404 路径不对）。
- 用 `urllib` 直接发请求而非 OpenAI SDK 的 `models.list()`——后者把路径写死为 `/models`，无法支持「兼容设置」里的自定义路径。

### 6. `llmconfig.json` v2 结构（连接 → 模型）

```json
{
  "version": 2,
  "active_model_id": "m_xxx",
  "connections": [
    {
      "id": "c_xxx",
      "provider": "deepseek",
      "name": "DeepSeek",
      "base_url": "https://api.deepseek.com",
      "api_format": "chat_completions",
      "api_key": "sk-xxx",
      "custom": false,
      "compat": { "models_path": "/models" },
      "models": [
        {
          "id": "m_xxx",
          "model": "deepseek-v4-flash",
          "display_name": "deepseek-v4-flash",
          "enabled": true,
          "tags": ["1M"],
          "context_in": "",
          "context_out": "",
          "capabilities": { "input": ["text"], "output": ["text"] },
          "capability_source": "auto",
          "advanced": { "temperature": "0.7" }
        }
      ]
    }
  ]
}
```

- `active_model_id`：全局激活（当前使用）模型；为空时取**首个启用模型**；皆无则 `null`（未配置态）。
- `connections[].custom`：是否为自定义供应商（非预置目录）。
- `connections[].compat`：兼容设置（当前仅 `models_path`）。
- `models[].capabilities` / `capability_source`：能力声明与来源（auto 自动识别 / manual 手动覆盖）。
- `models[].context_in` / `context_out`：模型级上下文与输出上限（空 = 继承）。
- `models[].advanced`：采样与思考等进阶项（可选，任一项填写才落盘）。
- 未知字段**全部保留**（`_normalize_model` 以 `dict(m)` 为底），向前兼容。

**v1 → v2 自动迁移**：读到旧格式（顶层扁平 `models[]`，每条自带 `provider`/`base_url`/`api_key`）时，按 `(provider, base_url, api_key)` 聚合为连接、模型挂到对应连接下，并**就地写回 v2**（`load_llm_config()` 内一次性执行，幂等）。同时把 `advanced.context_in/context_out` 提升为模型级 `context_in/context_out`。

**扁平兼容视图**：`get_config()` 额外下发一份 `models[]`（每条补 `connection_id` / `provider` / `base_url` / `api_key` / `connection_name`），使**输入区模型下拉、会话模型绑定、`resolveModelMeta`、`apply_to_env`** 等既有链路零改动。前端 `LlmModel` 即为该视图，`LlmConnectionModel` 为连接内条目。

### 7. 预置厂商公共元数据（`~/.aigent/providers.json`）

见 05 篇「预置厂商目录」——厂商名、默认 `base_url`、`api_format`、`api_key_env`、`docs_url` 与候选模型的 `tags`/`capabilities`/`max_context(_extended)`/`thinking_strengths`/`default_thinking`。加载时**内置为底、文件逐条覆盖、结果自愈回写**，因此：

- 官方上新模型时，只需更新 `agents/llm_config.py` 的内置目录，用户既有 `providers.json` 会自动补全（无需手改）；
- 用户也可直接编辑该文件增加自己的预置厂商（无密钥，安全）。

本期预置厂商仍为 **DeepSeek** 与 **硅基流动**；其它厂商一律走「自定义供应商」。

### 8. 高级设置 → env → 模型实例 映射表

| 配置项 | env（`apply_to_env` 写入） | Agent 实例消费点 |
| --- | --- | --- |
| `context_in`（模型级） | `OPENAI_CONTEXT_WINDOW_IN` | 暂作记录（落盘 + 下发），未参与运行时逻辑 |
| `context_out`（模型级） | `OPENAI_MAX_OUTPUT_TOKENS`（`1M/128k/8000` → token 数，k=1000、M=1000000） | `ErrorRecovery(default_max_tokens=)` → 每轮 `max_tokens` |
| `capabilities.input` 含 `image` | `OPENAI_IMAGE_INPUT`（1/0） | 能力标记，暂作记录 |
| `advanced.temperature` | `OPENAI_TEMPERATURE` | `_advanced_llm_kwargs()` → `create(temperature=)`（截断 0~2；未配置走 0.5） |
| `advanced.top_p` | `OPENAI_TOP_P` | 同上 → `top_p`（截断 0~1） |
| `advanced.top_k` | `OPENAI_TOP_K` | 同上 → `extra_body={"top_k":}` |
| `advanced.tool_rounds` | `OPENAI_TOOL_ITERATIONS` | `self.max_agent_iterations` → agent 循环上限（默认 100） |
| `advanced.thinking` | `OPENAI_THINKING_MODE`（default/enabled/disabled） | disabled → `extra_body={"thinking":{"type":"disabled"}}` |

主模型切换时旧高级 env 全量清除后按新主模型重写，避免残留；重载链路与既有热切换一致。`apply_to_env` 写入 `OPENAI_BASE_URL` 前会做 `normalize_base_url()`，保证 OpenAI SDK 能用。

### 9. 热切换架构（进程内重绑定）

运行时用到的 LLM 绑定共 6 处，全部在 Agent 实例内部：

| 绑定 | 持有对象 | 热切换方式 |
| --- | --- | --- |
| 自身主/备模型 | `self.model` / `self.fallback_model` | 重读 env 赋值 |
| 主 LLM 客户端 | `self.llm_client` | `LLMClient().llm` 重建 |
| 错误恢复 | `self.recovery` | 重建 |
| 工作流子智能体 | `workflow_manager` | `set_llm()` |
| 目标评估器 | `goal_controller` | `set_llm()`（不丢目标状态） |
| 子智能体 / 队友协作 | `subagent_runner` / `teammate_manager` | `set_llm()` |

```
前端保存 → ws llm_config_save
  → save_config() 落盘（0600，归一化为 v2）
  → load_llm_config()  映射进 env
  → Agent.reload_llm_bindings()  就地重建 6 处绑定
  → registry.reload_llm_bindings()  同步所有运行时会话 Agent
  → 立即生效，无需重启
```

### 10. 对话区模型下拉实时同步

- **数据源**：输入区（`components/Chat/InputBox.tsx`）读 `agentStore.llmConfig.models`（**扁平视图**）枚举**已启用**模型；当前激活项与后端 `apply_to_env` 的 primary 推导一致。
- **实时同步**：设置页增删/启停/设为当前后 `llm_config` 事件回写 store，下拉即时刷新。
- **切换即热生效**：下拉选模型 → `setSessionModel(id)` → 写会话元数据（`session_model`）；全局「当前」模型由设置页或 `setActiveModel` 改 `active_model_id`。
- **启动即知**：`App.tsx` 监听 `connection === 'connected'` 后调一次 `loadLlConfig()`。
- 模型小圆点改用 `providerDot()`：`deepseek → dp`、`siliconflow → sf`、其它（含自定义）留空走中性样式。
- 未配置任何模型时按钮禁用，文案「未配置模型」。

## 三、落地

### 后端 `agents/llm_config.py`

- 常量：`LLM_CONFIG_FILE = AIGENT_HOME/"llmconfig.json"`、`PROVIDER_CATALOG_FILE = AIGENT_HOME/"providers.json"`、`API_FORMATS`（下拉候选）。
- `_DEFAULT_CATALOG`：内置预置厂商目录（首次运行物化写出；DeepSeek / 硅基流动）。
- `load_provider_catalog()` / `save_provider_catalog()`：读取 + 按模型合并 + 自愈回写。
- `normalize_base_url()`：完整请求地址 → SDK 可用 base\_url。
- 归一化：`_normalize_model()` / `_normalize_connection()` / `ensure_v2()`（含 `_migrate_v1_connections()`）/ `_flatten()`。
- `get_config()`：返回 `{version, active_model_id, connections, models(扁平视图), providers, api_formats}`。
- `save_config(data)`：v1/v2 输入统一归一化 → 落盘 0600（**允许空 connections**：删光 → `active_model_id: null`）。
- `apply_to_env(data)`：主/备模型 + 模型级上下文/能力 + `advanced` → env（密钥为空**不覆盖**既有 env key）。
- `load_llm_config()`：文件存在才加载；**检测到 v1 即迁移并写回 v2**。
- `fetch_remote_models(base_url, api_key, connection_id, models_path, timeout)`：`GET` 拉模型列表，返回 `{ok, models, base_url?, error?}`。
- 会话级换绑临界区（`ENV_LLM_LOCK` / `snapshot_llm_env` / `restore_llm_env` / `apply_model_to_env`）保持不变。

### 启动挂载

- `agents/agent_cli.py` `main()`：`load_config()` 后再 `load_llm_config()`。
- `agents/ws_bridge.py` 模块顶部：`load_config()` 后再 `load_llm_config()`，早于 `Agent(...)` 实例化。
- 注意：`agent_full_v2` import 期 `load_dotenv(override=True)` 会把 `.env` 覆盖进 env；`apply_to_env` 用直接赋值因此仍能胜出。

### 关键取舍

- **连接层 vs 扁平层并存（临时但必要）**：磁盘只存 `connections`（单一事实源，无冗余），API 响应额外派生扁平 `models` 视图。代价是响应体积略大，收益是输入区/会话绑定等链路零改动、可平滑演进（后续若全部改为连接寻址，删掉派生即可）。
- **模型 ID 自由输入而非下拉限定**：这是本期痛点的根因修复。下拉只作「候选与自动识别」用途，不再作为唯一入口。
- **「刷新」用 urllib 而非 SDK**：为了支持「兼容设置」里的自定义模型列表路径，并让 HTTP 错误码/响应体可回显。
- **密钥同文件**：为表达结构化多连接仍暂放 `llmconfig.json`（0600）。未来如需更高隔离可把 `api_key` 抽出到钥匙串，结构不变。
- **编辑不回显为「已保存」态**：API Key 直接以密文框回显（本地单机产品，追求「打开即改」的顺手），保存即覆盖。
- **编辑先落草稿**：避免半途改动（如刚改了 base\_url 就触发热切换）导致运行中断；「保存更改」是唯一的生效临界点。
- **任何模型都可删除**、**任何连接都可删除**：删光后 `save_config` 落盘空结构，`apply_to_env` 清掉模型 env（key/base\_url 保留），`reload_llm_bindings` 返回「无启用模型」，不会出现用已删除模型继续对话的静默错误。

## 四、验证

1. **后端单测（临时替换 `LLM_CONFIG_FILE` / `PROVIDER_CATALOG_FILE`）**：v1→v2 归一化（连接聚合、`advanced.context_out` 提升、预置元数据继承）、v2 落盘 round-trip、0600 权限、自定义厂商与自定义模型、`apply_to_env` 映射（`context_in/out` → token 数、`capabilities` → 图片标记）、`normalize_base_url`、空配置兜底、`fetch_remote_models` 参数校验、`providers.json` 物化与合并自愈幂等。
2. **真实链路**：在真机 `~/.aigent/llmconfig.json` 上跑 `load_llm_config()` 验证自动迁移；用真实 DeepSeek 密钥调 `fetch_remote_models()` 验证「刷新」返回可用模型 id（实测拉回 `deepseek-flash` / `deepseek-v4-pro`）。
3. **端到端（`frontend` 下 `npm run dev`）**：点齿轮 → 居中弹窗、左栏`通用/模型/回收站/关于` → 模型页左侧出现 DeepSeek 连接 → 右侧改 API Key → `⟳` 刷新 → 列表追加远端模型 → 勾选/设为当前 → `保存更改` → toast「模型配置已生效」→ 下一轮对话即用新模型（无需重启）。
4. **自定义厂商**：`+ 添加模型服务` → 自定义供应商 → 填名称/地址/密钥 → 手填一个模型 ID → 保存 → 左侧出现新连接 → 输入区模型下拉可选到它。
5. **热切换回归**：停用当前主模型 → primary 自动落到下一个启用模型；删光所有连接 → 回到未配置态。
6. **缺文件场景**：删除 `~/.aigent/llmconfig.json` 后重启，后端照常走原有兜底配置。
