# 桌面端前端设计文档（目录导航）

本目录存放 **TraeWork 复刻桌面端（Electron + TypeScript）** 的完整设计与开发文档。
后端是已有的 Python Agent（OpenAI SDK 流式改造版），前端作为其 UI 壳。

> 阅读建议：完全零基础 TS / Electron 的读者，请从 `01-技术框架设计.md` 开头的「前置概念」读起，
> 每个文档都按「概念 → 设计 → 落地」的顺序组织，配套学习资源在文末给出。

## 核心结论（速览）

- **技术栈**：Electron + TypeScript + React，构建用 Vite，样式用 CSS（模块化）。后端 Python 以**子进程**方式由 Electron 拉起，通过 WebSocket 通信。

- **前端边界**：前端只负责「渲染 + 交互 + 把用户意图转发给后端」，所有 Agent 逻辑、工具执行、流式生成都在 Python 后端。

- **数据通道**：后端 `WSSink` 已能产出 JSON 行协议事件（thinking / content / tool\_call…），前端按行解析还原成消息流。

- **复刻范围**：初期严格复刻截图所示——左侧边栏（快捷操作 / 任务树 / 用户信息）+ 中央聊天面板（空态品牌 + 多行输入框 + 工具栏 + 快捷命令 chips）。

- **三条正交的管控轴（别把它们混成一件事）**：
  - **权限轴**（17 篇）：这个操作「**允不允许 / 要不要审批**」—— 规则级，`permission_mode ∈ {default, full_access}`；
  - **沙盒轴**（20 篇）：命令在 OS 层「**实际能碰什么**」—— 执行期，`full_access` 免审批**不免墙**；
  - **执行模式轴**（22 篇）：这一轮任务「**以什么方式干**」—— 模式级，`execution_mode ∈ {normal, plan, goal}`，`full_access` 免审批**不免模式墙**（plan 下写操作照样被拦）。
  三者**判定链不合并**，各判一次，互补不可互替。

- **后续增量**：对话历史管理、自动化、认证等，后端暂无对应接口，列为独立增量任务。（**MCP 市场**见 23 篇；**技能市场**见 24 篇（多源聚合：git 仓库 / 第三方 API / 自建索引）；**插件市场**见 25 篇（对齐 Claude Code 插件规范，兼容即市场）。三者共用同一套面板语言与协议约定。）
