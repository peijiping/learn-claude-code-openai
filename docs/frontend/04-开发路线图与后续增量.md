# 04 - 开发路线图与后续增量

按「先跑通核心对话 → 再补界面细节 → 最后扩展后端缺的能力」的节奏推进。
目标：**用尽量少的改动，先让"输入 → 流式打字机 → 工具折叠条"这条主链路跑起来**，
因为这是后端当前唯一能稳定提供的价值。

---

## P0 — 工程骨架启动（壳）

**目标**：能打开一个 Electron 空窗口。
- 用 `npm create @quick-start/electron` 生成 TS + React + electron-vite 骨架。
- 建目录结构、设计系统 `tokens.css`、z-index/布局骨架。
- 三栏空布局：侧边栏 / 中央 / 隐藏右栏。

✅ 验收：`npm run dev` 打开一个空白三栏窗口，无报错。

---

## P1 — 布局与静态界面（不连后端）

**目标**：把截图静态复刻出来。
- 侧边栏：快捷操作 / 任务列表（写死样例数据）/ 用户卡。
- 中央：空态品牌 + 输入框（textarea + 工具栏 + 上下文 + 快捷 chips）。
- 样式完全按 Doc02 的 design tokens。

✅ 验收：界面与截图观感一致；输入框可输入、Enter 发送（本地仅打日志）。

---

## P2 — 后端桥与核心对话链路（主线打通）

**目标**：接入真实后端，实现流式打字机。
- 新增 Python `ws_bridge.py`（Doc03 第 5 节），Electron 主进程拉起并连接。
- 实现主进程 WS 客户端、preload、`useAgentStream`。
- 渲染：`content_delta`/`thinking_delta` → 打字机；`turn_end` → 收尾。
- 断线重连与"重新连接"提示。

✅ 验收：输入一句话，界面上逐字出现后端回复；能收到 usage。

---

## P3 — 工具调用可视化与稳定性

**目标**：补全交互与健壮性。
- `tool_call_start/_delta/tool_call` → 只读工具折叠条。
- 发送中禁用、停止按钮、加载状态。
- Python 崩溃自动重启、WS 异常恢复。
- 会话操作（新建/切换/清空）接入任务列表。

✅ 验收：工具调用可见；连续多轮对话不丢消息、不卡死。

---

## P4 — 目标 / 待办 / 技能等浅接入

**目标**：接入后端剩余能力（只读展示）。
- 目标进度、待办看板、技能列表 通过协议拉取并展示（对应界面预留位）。
- 任务树改为读后端会话列表并支持切换。

✅ 验收：设置弹窗能显示技能/待办；任务树可切换会话。

---

## 后续增量（后端暂无对应能力，逐个补齐）

按"后端接口 → 前端界面"的顺序，每项都先在后端补接口（可能是 Python 或新增模块），再在不破坏现有协议的前提下加 `kind` / 界面。

| 增量 | 说明 | 依赖 |
|------|------|------|
| 模型管理 | 模型下拉真实可选，可配多模型 / provider / key | 后端需暴露模型列表与切换能力（现仅 `.env` 单模型）|
| 对话历史管理 | 历史/搜索/重命名/删除 | 后端 session 元信息接口完善（文件名→标题/时间）|
| 权限控制 | "完全访问"下拉真实生效 | 后端权限校验接口（已有 `check_permission`，需暴露）|
| 附件/图片 | `📎` `📊` 传文件给后端 | 后端需支持多模态/文件输入通道 |
| 插件市场 / 模板库 / 自动化 / 办公助理 | 侧边栏占位变为真实功能 | 后端需分别提供插件、模板、调用能力 |
| 账号 / 认证 / 订阅 | 用户卡真实化 | 后端无账号体系，需新增服务或走远端 |

> 每项增量都会先更新 Doc02（UI）与 Doc03（协议）再实现，避免框架设计与落地脱节。

## 迭代原则（贯穿始终）

1. **单条链路打穿**：不一次做所有功能，先把"输入→流式→展示"跑通。
2. **后端零改动**：新增能力一律走后端新增薄接口/薄桥，不动 `agent_full_v2.py`。
3. **协议先行**：任何新界面功能先定义 `kind` 与事件类型，前端按协议实现。
4. **可回退**：每阶段独立成提交，坏了能单独回退。
