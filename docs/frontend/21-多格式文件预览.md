# 21 - 多格式文件预览（图片 / PDF / Office / 正文路径链接）

> 状态：已实现（2026-09-23）。前置：19-右侧面板（文件与变更）、13-引用、15-统一文件读取。

## 1. 需求

对话界面内出现的文件（模型输出的路径文本、`file://` 链接、@ 引用胶囊）点开后，直接在右侧面板以**独立 tab 页**只读预览；覆盖 **图片 / PDF / Word / Excel / PPT**；**目录**点开则定位到右栏「文件」视图（没开就自动添加并打开），不再弹系统文件管理器。

## 2. 决策记录（先讨论后拍板）

| 问题 | 决策 | 理由 |
|---|---|---|
| 图片/PDF 怎么渲染 | Electron 内置（`<img>` / `<embed type="application/pdf">`） | 真机探针验证：内置 Chromium PDF viewer 可渲染自定义协议直读的 PDF，**零体积、零依赖** |
| Office 怎么渲染 | **运行时探测 LibreOffice → 转 PDF**；没装则文本抽取降级 | LibreOffice 打包 +794MB 被用户否决；纯 JS 预览库 +0.7~1MB 且保真差。探测到就用（体积 0 增量），没装也能看文字 |
| 会话内点文件落哪 | **常驻位**（独立 tab，互不顶替，上限 12 枚） | 用户拍板"独立的 tab 页"，推翻了旧"预览位就地顶替"语义 |
| 正文裸路径识别范围 | **白名单精确匹配**（工作空间文件列表）+ `file://` 链接映射 | 绝不出现"点了没反应"的假链接；`../` 前缀刻意不剥防错配 |

## 3. 数据流与模块分工

```
点开文件 → file_read（WS，只传路径）
  后端 refs.read_workspace_file()
    ├─ resolve_within（沙箱判定，与引用/safe_path 同一条链）
    ├─ classify_preview_kind：扩展名优先、魔数兜底 → kind
    │   image/pdf：一个字节正文都不读（回执只带元数据）
    │   office：LibreOffice 转 PDF（缓存 .aigent/office-preview/），失败降级文本
    │   text/binary：原有逻辑
    └─ file_content 回执 {kind, pdf_path?, office_hint?, ...}
渲染层 rightPanelStore.applyFileContent（唯一收口）
  ├─ reportFileStream([path | pdf_path]) → 主进程白名单
  └─ FilePreview 按 kind 分支渲染：
      image → <img src="aigent-file://local/?path=...">
      pdf / office(pdf_path) → <embed type="application/pdf">
      office(text) → 代码视图 + office_hint 横幅
      text / binary → 原有行为
```

**为什么图片/PDF 不走 WS 传字节**：websockets 帧上限 1 MiB，base64 必超；与附件缩略图（`aigent-att://`）同一条"主进程喂文件"路线。

## 4. `aigent-file://` 协议与安全模型（主进程）

- **privileged 注册**（`registerSchemesAsPrivileged`，`standard+secure+supportFetchAPI+stream`）必须在 `app ready` 之前。
- handler：`?path=<encodeURIComponent(abs)>` → realpath 归一 → **白名单校验** → statSync（文件 + ≤64MB）→ readFileSync → 按扩展名给 Content-Type。
- **报备制白名单**（`allowFileStream` IPC）：渲染层收到 `file_content` 回执后把要展示的路径报备进 `streamAllowed`（realpath 归一、必须实存文件、FIFO 上限 200）。**只有后端 file_read 回执真正给出去过的路径才可能被读**——白名单边界与后端沙箱完全一致，主进程无需知道各项目 workdir。
- **MIME 白名单刻意收窄**：只有图片 + PDF 共 12 种扩展名；`.html/.htm/.js` **不在表里**，报备了也 403 —— 工作空间 HTML 只走文本预览，绝不作为文档渲染（同 refs.py 取舍）。
- **SVG 响应强制 `Content-Security-Policy: script-src 'none'`**：`<img>` 加载 SVG 不执行脚本，但若被误用 `<embed>/<iframe>` 加载就会——响应头 CSP 焊死这条路。
- **CSP（renderer/index.html）**：`img-src` 放行 `aigent-file:`；**`object-src` 必须显式写 `'self' aigent-file:`** —— 真机探针实测：漏写 `object-src` 时回落 `default-src 'self'`，PDF 的插件数据加载被静默拦截，症状是 **PDF 区域全灰转圈、控制台仅一条 CSP 告警**。这是本功能最隐蔽的坑。
- `webPreferences.plugins: true`：内置 PDF viewer 的开关，缺了 `<embed>` 也不渲染。

## 5. 后端分派（refs.py）

- `classify_preview_kind(path, head)`：扩展名表（`IMAGE_PREVIEW_EXTS` / `.pdf` / `OFFICE_PREVIEW_EXTS`）优先，`_sniff_kind`（`%PDF-`、PNG/JPEG/GIF/WEBP 魔数）只做兜底。扩展名撒谎会被魔数纠正（`.txt` 里装 PNG 仍能预览）。
- **图片/PDF 分支一个字节正文都不读**，只回元数据；`too_large` 阈值用流式上限 `FILE_STREAM_MAX_BYTES`（默认 64MB，`FILE_STREAM_MAX_BYTES` 可调），与文本的 512KB 是两个量级、两个用途。
- **Office**（`convert_office_to_pdf`）：
  - `libreoffice_binary()` 运行时探测（平台默认路径 → PATH → `LIBREOFFICE_PATH` 环境变量），进程内缓存"没装"结论；
  - 转换产物落 `<workdir>/.aigent/office-preview/<key>/<stem>.pdf`，键含 `mtime_ns+size`（源一改键就变，无需精确 GC）；`.aigent` 在 `DEFAULT_IGNORE_DIRS` + 目录内 `.gitignore`；
  - 转换用**独立 profile**（`-env:UserInstallation=`）——用户自己开着 Writer 时不被锁卡死；
  - 超时 `OFFICE_CONVERT_TIMEOUT`（默认 90s）；失败/没装 → `_office_text_fallback`（`doc_convert.convert_office` 文本抽取）+ `office_hint` 人话原因。
- `file_content` 回执新增字段：`kind`（'text'|'image'|'pdf'|'office'|'binary'）、`pdf_path`、`office_hint`。失败形态（`file_content_disabled`）同一套字段。

## 6. 正文路径链接（lib/pathLinks.ts）

- **remark 插件**（mdast 层）：text 节点内的 token（`[A-Za-z0-9_@.\-/]+`）**逐字命中**工作空间文件列表（`buildPathIndex`：相对 + 绝对两种键，含 dir）才变成内部链接 `aigent-ref:<enc(abs)>[?d=1]`；`code/inlineCode/image` 子树跳过，`link` 节点单独处理。
- **`file://` 链接就地映射**：大模型爱写 `[文件名](file:///abs/path)`（真实会话实测形态），渲染层既过不了 CSP 也过不了 urlTransform，点击注定无效；命中列表时改写成 `aigent-ref:`。`new URL().pathname` + `decodeURIComponent` 天然处理中文文件名与 `#L行号` 锚点。
- token 预处理：剥 `./` 前缀（真实形态 `./data/attachments/full.png`）；**剥 `../` 会错配顶层同名文件，刻意不做**；首尾标点修剪（句号不在字符类内自然断开）。
- react-markdown v9 需自定义 `urlTransform`（`safeUrlTransform`）：默认清洗会把 `aigent-ref:` 清成空串；恒等放行又会让 `javascript:` 活过来。镜像默认白名单、只多放行**内部协议 + `file:`**（`file:` 放行只为让 `a` 组件拿得到原值走兜底，见下条）。
- 树未加载 / 空索引 → 插件不进 `remarkPlugins` 数组，零开销直通（正文原样）。
- 索引与右栏树**同源**（`refs_list` 回执），未列出的路径不进索引 —— **但"未进索引"只影响渲染形态（点线 `.md-path-link` vs 虚线 `.md-path-link-unknown`），不影响可点性**，见 §6.1。
- **渲染层不再把任何本地路径渲染成 `<a>`**：命中索引 → `aigent-ref:` 按钮；未命中 → `localTargetOf` 兜底按钮。详见 §6.1。

## 6.1 本地路径兜底与「绝不整页导航」契约（2026-09-23 事故修复）

**事故现象**（用户实测）：重启应用后打开一个会话，点正文里的 `[xxx.pdf](file:///…)` / `[xxx.png](file:///…)` 链接，**直接跳到"新建任务"态** —— 会话没了。

**根因链**（headless 实测复现，`boots` 计数 1→2 + `Page.frameNavigated`）：

1. 文件列表**只有打开右栏「文件」视图才会拉**（`RightPanel` 的 `ensureTree` 在视图标签激活时才调用；会话 `right_panel: null` = 从没开过）。
2. 列表没加载 → `pathIndex` 空 → remark 插件不进数组 → `file://` 链接**不改写**。
3. `file:` 被 `safeUrlTransform` 清成空串 → 渲染出 **`<a href="">`**。
4. `href=""` 在浏览器语义里 = "导航到当前文档 URL" = **整页重载**（dev 下就是 http://localhost:5173/）→ 渲染层重启 → `activeSession` 归零 → 回到新建任务态。

**修复（两道，缺一不可）**：

- `safeUrlTransform` **放行 `file:`**（不清成空串）—— 否则 `a` 组件再也认不出它是本地路径。
- `a` 组件分派（`MessageItem.MarkdownBody`）：
  | href 形态 | 渲染 | 点击行为 |
  |---|---|---|
  | `aigent-ref:`（索引命中） | `button.md-path-link` | `onOpenPath(abs, isDir)` |
  | `file:` / 无协议相对路径 | `button.md-path-link.md-path-link-unknown` | 同上（**原样送右栏**，可读性由后端 `resolve_within` 裁决；越界时预览区给原因） |
  | `http(s)` / `mailto` / `//host` | `<a target="_blank" rel="noreferrer noopener">` | 交给主进程 `setWindowOpenHandler` → `shell.openExternal`，**本窗口绝不导航** |
  | `#锚点` | `<a href="#…">` | 只改 hash，不离开应用 |
  | 其余（`javascript:`/`data:` 已被清空、空串） | `<span>` | 不可导航 |

**契约（后续任何人加正文链接渲染都必须满足）**：渲染层**永远不能**产出会让主窗口导航的元素。`<a href="">`（空串）、相对路径 `<a>`、`file://` `<a>` 三者都会整页重载 —— 代价是用户丢掉当前会话。判定本地路径用 `lib/pathLinks.ts::localTargetOf`（统一收口，别在组件里另写一套）。

**顺带修掉的同类缺陷**：`https://` 外链此前是裸 `<a href>` → 点了**主窗口直接导航走**（应用整个消失），现改为 `target=_blank` 由主进程外开。

## 7. 点击落点（rightPanelStore）

- `revealFile(sid, path, name)` → `openFileTab(..., 'tree')`：**落常驻位**（pinned:true，独立 tab）。同文件已开 → 只激活；超 12 枚淘汰最旧的非激活常驻 tab。旧"chat 来源落预览位"语义已废弃（`FileTabOrigin` 类型保留，预览位仅随 normalize 容错旧数据存在）。
- `revealDir(sid, path)` → `openViewTab('files')`（「文件」视图标签没开就自动添加并激活）+ `ensureTree` + `expandTo`（祖先链展开；树未加载时挂 `pendingReveal` 回执后补展开）。
- `MessageItem.openRef`：文件 → `revealFile`；目录 → `revealDir`；**附件不在此列**（会话副本不在工作区，保持 Finder）。
- 传入的 `path` 允许是**绝对路径**（`file://` 兜底、索引命中）或**工作空间相对路径**（正文里写 `[x](./a.md)`）：后端 `refs.resolve_within` 相对路径按工作空间根解析，越界/不存在返回原因而不是抛错。

## 8. FilePreview 渲染分支与状态优先级

`传输错误 > loading > reason(读失败) > too_large(整屏替换) > binary(平级空态) > kind 分支(image → pdf → office) > text(带截断横幅)`。

媒体分支额外有 `mediaFailed` 兜底：`<img>` error / `<embed>` 无法重载时给「重试」按钮（重新报备 + nonce 重建元素 + 重读）。headless 环境协议不存在时落此态（验证了兜底通路）。

CSS：`.rpanel-media-wrap`（深底衬 + `margin:auto` 居中）/ `.rpanel-media`（`max-width/height:100%` 等比缩到容器内）/ `.rpanel-pdf`（`flex:1` 撑满）；正文链接 `.md-path-link`（accent 色 + **点线**下划，索引命中）/ `.md-path-link-unknown`（**虚线**，未命中兜底，`text-decoration-style` 覆盖）/ `:disabled`（无 `onOpenPath` 时灰掉）。

### 8.1 媒体面高度链（2026-09-23 二修，事故）

**现象**（用户实测）：PDF 标签的**默认显示高度太低**（只占面板顶部一小条）；图片标签**根本预览不了**（整屏空白）。

**根因**：三条媒体样式（`.rpanel-media-wrap` / `.rpanel-media` / `.rpanel-pdf`）被写进了仓库**根目录**下的一个游离 `rightpanel.css`，而 `renderer/src/main.tsx` 引的是 `styles/rightpanel.css` —— **规则从未生效**（游离 `.css` 不报错、typecheck/build 全绿、组件分支断言也全过）。表现：

- `<embed>` 无尺寸时是 **300×150** 的替换元素（`align-self:stretch` 只让它宽铺满）→ 可用高 794px 里只占 150px（18.9%）；
- `11250×7508` 的截图按**原始像素**渲染 → `.rpanel-media-wrap` 被撑到 7511px 高，`.rpanel-preview` / `.rpanel-body` 双双溢出滚动，可视区只看得见图片左上角（用户看到的就是"空白"）。

**修复**：三条规则搬进 `styles/rightpanel.css`（`main.tsx` 真正引入的那个），并顺手把居中改为**子元素 `margin:auto`**（父级 `align/justify-center` 在"内容比容器大"时会把溢出推到滚动不可达的负方向，`auto` 边距溢出时归零、两端都够得着）；删掉游离文件。

**高度链（改这一块先把这条链看清，任何一环塌了都是"媒体面高度不对"）**：

```
.rpanel             flex column, min-height:0（inline width）
 └ .rpanel-inner    flex:1, min-height:0
    └ .rpanel-body  flex:1, flex column, min-height:0
       └ .rpanel-preview  flex:1, flex column, min-height:0
          ├ .rpanel-head   flex:none（32px）
          └ 媒体面         flex:1, min-height:0   ← 缺这条就塌
```

**约定**：

1. 媒体面（`.rpanel-media-wrap` / `.rpanel-pdf`）**必须自己 `flex:1` + `min-height:0`**；`<embed>` 不会"自动铺满"，`<img>` 也不会"自动缩放"。
2. 宿主 DOM 必须能给媒体面**确定高度**（上一轮验证把 `FilePreview` 挂在无高度的 `#fp-root` 里 → 量不到高度 → 这个缺陷当时漏过）。
3. **新增样式文件后必须确认它在 `main.tsx` 引入的那 7 个 `.css` 里**（`tokens/global/layout/sidebar/chat/rightpanel/settings`）；游离的 `.css` 静默不生效。

## 10. 已知边界

- Office 降级文本无版式（如实告知 `office_hint`）；`.doc/.xls/.ppt/.odt/.ods/.odp` 只有 LibreOffice 在场才能预览（文本抽取只认 ooxml 三件套）。
- 首次预览 Office 要等 LibreOffice 冷启动（3~8s），之后命中缓存秒开。
- 会话内文件标签落常驻位后，预览位仅剩历史数据归一化语义；后端 `normalize_right_panel` 无需改动（字段不变，只是前端来源变化）。
- **未命中索引的本地路径**（树没加载 / 路径在工作空间外 / 列表被截断）：点开会让右栏发一次 `file_read`，越界或不存在时在预览区给原因，**标签仍会开出来**（不做"先探测再决定"——探测本身就是同一次后端调用）。这是刻意取舍：宁可"点得开但可能读不到（有原因）"，也不要"点了没反应"或"点一下就重载"。
