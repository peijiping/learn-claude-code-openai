# 19 - 右侧面板（文件与变更）

右栏从 `02` 篇里那句「右栏默认隐藏，后期用于工具执行详情 / 文件查看」推进成**可用的多标签工作区**。
本期交付 **文件** 与 **变更** 两个视图；**终端** 与 **浏览器** 在「+」菜单里占位（置灰 + 「第二期」微标），
契约与状态模型已按四项设计，第二期只需补视图实现，不动协议。

> 一句话核心：**右栏是会话的私有财产** —— 一个会话一份实例，开没开、开了几个标签、哪个标签激活、
> 每个标签滚到哪儿，全部随会话走，会话之间互不干扰。

***

## 一、为什么是这样（三个决策）

### 1.1 为什么要按会话隔离

同一个工作空间下，A 会话在读 `agents/tools.py`，B 会话在改 `frontend/src/App.tsx`。
如果右栏是全局单例，切会话时上一条会话的标签会留在栏里 —— 用户会以为「这个文件是当前会话打开的」，
点关闭时又不知道该关谁。所以右栏的**全部**可见状态都必须按会话分桶。

### 1.2 为什么载体是**会话元数据**而不是 `localStorage`

这是本期最关键的一次取舍。三个候选：

| 方案 | 切会话恢复 | 跨重启 | 多窗口一致 | 结论 |
| --- | --- | --- | --- | --- |
| 纯内存（React state） | ✅ | ❌ | ❌ | 重启即丢，不可接受 |
| `localStorage` | ✅（自己按 sid 分桶） | ✅ | ❌ 各窗口各写各的 | 会与后端已落盘的会话状态**产生两个真相源** |
| **会话元数据 `session_<sid>.meta.json`** | ✅ | ✅ | ✅（随 `session_history` 下发） | **选用** |

选元数据是因为**先例已经在那儿**：`unread`、`permission_mode`、`usage_totals`、`model_id`/`overrides`
都是这么存的，且切换会话时随 `session_history` 一起回传（`03` 篇 §2.1）。加一个字段的边际成本
接近于零，却白拿了跨重启与多窗口一致。`localStorage` 只有一个位置还留着 —— **右栏宽度**
（见 §5.3），因为宽度是「这台机器的屏幕偏好」，不属于任何会话。

> ⚠️ 反面教材就在隔壁：`18` 篇第 11 条踩坑 —— `permission_config` 的回包是**补丁**不是快照，
> 消费端整份替换导致保存后整页塌成加载态。本期的 `applySessionUi` 因此带**桶存在即忽略**的守卫，
> 理由同理：不知道对面发来的是全量还是补丁时，宁可只认第一次。

### 1.3 为什么标签栏是**单栏混放**而不是双栏

候选：① 视图标签与文件标签分两栏；② 单栏混放。

选②。理由是**同类关系**：`文件`视图和它打开的文件，是「同一件事的不同层级」，分成两排会让
"我现在在看哪个"变成两个地方都要看。单栏混放下用户扫一眼就知道全貌，代价只是要有一套
身份区分（见 §3.2），而那本来就要做。

## 二、数据模型

### 2.1 持久部分 `RPanelPersist`

落 `session_<sid>.meta.json` 的 `right_panel` 字段：

```json
{
  "open": true,
  "tabs": [
    { "kind": "view", "view": "files" },
    { "kind": "file", "path": "/abs/path/agents/tools.py", "name": "tools.py", "pinned": true },
    { "kind": "file", "path": "/abs/path/App.tsx", "name": "App.tsx", "pinned": false, "origin": "chat" }
  ],
  "active": "file:/abs/path/agents/tools.py"
}
```

| 字段 | 说明 |
| --- | --- |
| `open` | 右栏是否展开。**收起右栏不关标签** —— 两者正交 |
| `tabs` | 单栏混放的有序标签列表 |
| `kind` | `"view"` 视图标签 / `"file"` 文件标签 |
| `view` | 仅 `kind="view"`：`files` / `changes` / `terminal` / `browser` |
| `path` / `name` | 仅 `kind="file"`：**绝对路径** + 显示名（文件名，不是路径） |
| `pinned` | 仅 `kind="file"`：`true` 常驻位 / `false` 预览位（见 §3.1） |
| `origin` | 仅 `kind="file"` 且未 pinned：来源 `chat`（会话内链接）/ `tree` / `changes` |
| `active` | 当前激活的 **tab key**（`view:<view>` 或 `file:<绝对路径>`）；`null` = 无激活项 |

### 2.2 上限与归一化（后端 `session_manage.py`）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `RIGHTPANEL_VIEWS` | `("files","changes","terminal","browser")` | 合法视图白名单 |
| `RIGHTPANEL_MAX_FILE_TABS` | `12` | **常驻位**文件标签上限 |
| `RIGHTPANEL_MAX_TABS` | `17` | 总上限 = 4 视图 + 12 文件 + 1 |

`normalize_right_panel(ui)` 是**逐项丢弃**而不是整体拒绝：一个坏标签不会让整份布局回退成空。
丢弃规则：

- 非 dict / 非法 `kind` / 非法 `view` / 重复 `view` → 丢；
- 文件标签 `path` 不是非空字符串 → 丢；重复 `path` → 丢；
- 超出上限 → 先砍**常驻位**（`pinned` 从后往前），**预览位永远保留**（它只有一枚，且是用户
  刚刚点开的那一个，砍它比砍一个后台标签更让人困惑）；
- `active` 指向已不存在的 tab → 置 `null`（而不是"随便挑一个"，那会让界面在用户没操作时自己跳）。

`set_session_ui(session_id, ui)` 以 `touch=False` 写入 —— **点标签不算"会话内容变化"**，
不该把会话顶到列表最前。

### 2.3 前端两级内存结构

| 桶 | 生命周期 | 内容 |
| --- | --- | --- |
| `layoutBySession` | **长期保留**（每会话一份） | `RPanelPersist`，即上表结构 |
| `liveBySession` | **只留当前会话**，切走即丢 | 大块数据：`tree` / `preview` / `git` / `diffs` / 各种 loading |

分开的理由：布局是**用户意图**（贵、要留），内容是**可重取的缓存**（便宜、丢了再拉）。
只保留当前会话的 `live` 还有一个副作用是好的 —— 内存不会随会话数线性膨胀。

> ⚠️ **`liveBySession` 的桶不存在时绝不重建**（`mutateLive` 的守卫）。因为回执是异步的：
> 用户点了文件 → 切走 → 回执才回来。此时若 `mutateLive` 顺手建了一个桶，就等于给一个
> **已经切走的会话**凭空造了缓存。把它丢掉才是对的。

## 三、交互规格

### 3.1 两处入口，两种身份（本期核心区分）

**这是需求里点名要区分的一点**：从会话内文件链接打开的标签，和在右栏里点「+」/树打开的文件标签，
必须能看出不是一回事。

| | **预览位**（`pinned: false`） | **常驻位**（`pinned: true`） |
| --- | --- | --- |
| 落点 | 会话内点文件链接 | 树里点文件 / 变更行尾「在右栏打开」 |
| 数量 | **全场唯一** | 上限 12 |
| 再开一个 | **就地顶替**（不新增、不移动） | 新增一枚 |
| 位置 | 固定（第一次出现的那个位置） | 插在**最后一个「文件相关」标签之后**（§3.1.1） |
| 视觉 | **斜体** + 来源圆点（`title` = `来自会话链接 · <绝对路径>`） | 正体、无圆点（`title` = 绝对路径） |
| 升级 | 双击标签，或在树里再点一次这个文件 → 就地变常驻 | — |

「就地顶替」是这里的重点，也是**最容易实现错**的地方：如果实现成"关掉旧的、在末尾追加新的"，
用户刚点开两个文件时会看到标签在栏里**跳来跳去**。正确做法是**替换同位置上的那一枚**。

#### 3.1.1 新文件标签插在哪儿（2026-09-23 回归修复）

**规则**：新开的一枚文件标签插在**最后一个「文件相关」标签之后**。「文件相关」= `view:files`
视图标签，或任意一枚文件标签；一枚都没有时（例如只开着「变更」视图）才落栏尾。
实现在 `lib/rpanelTabs.ts::fileTabAnchor()`，是 `openFileTab` 里唯一的定位来源。

**为什么**：本栏是**单栏混放**，视图标签与文件标签同排。原先树里点文件是**一律追加到栏尾**，
于是出现这个用户实测报的场景 ——

```
改前： [文件] [a.ts] [终端]          点树里的 b.ts →  [文件] [a.ts] [终端] [b.ts(激活)]
                                                        ↑ 新标签跑到「终端」右边了
改后： [文件] [a.ts] [终端]          点树里的 b.ts →  [文件] [a.ts] [b.ts(激活)] [终端]
```

用户的原话是「文件 tab 打开在终端的左边，点击里面的某个文件打开时，文件 tab 会跳到终端的右侧」。
追加到末尾本身没错（它是"最近打开的在最右"），错在**栏里有视图标签时，栏尾并不挨着文件区**。

**为什么不是「文件标签永远排最后」/「永远紧跟 `view:files`」**：前者会把**已经开着的**
文件标签从「文件」视图后面推走（用户攒的标签位置还是会变），后者会把新标签插到已有文件标签
**前面**（已有标签集体右移）。现在的规则只决定「新标签插在哪」，**已有标签的相对顺序一枚都不动**。

预览位新增时也走这条（没有预览位可用时插到锚点处），所以从会话链接点开的文件同样不会跳到
视图标签右边；预览位「就地顶替」的语义不变（同位置换内容）。

`title` 为什么带前缀：预览位只有一枚，用户过一会儿就忘了它是从哪条消息点出来的。悬停给一句
`来自会话链接 · /完整/路径` 比只给路径有用（前者回答了"为什么它在栏里"）。

### 3.2 标签栏行为

| 操作 | 行为 |
| --- | --- |
| 点标签 | 激活（`active` = 该 key） |
| 关闭按钮 | 关闭该标签；**激活转移 = 右邻优先**，没有右邻取左邻；关光 → 欢迎态（**右栏仍开着**） |
| 中键点标签 | 关闭（浏览器/编辑器通用约定，比右键菜单快一步） |
| 双击**预览位** | 升级为常驻位（防被顶替） |
| 溢出 | 标签栏横向滚动；**「+」钉在栏尾不随滚动**；激活项自动 `scrollIntoView({inline:'nearest'})` |

### 3.3 开栏 / 收栏的入口

开关图标住在**窗口最外层的自绘标题栏**里（`.titlebar`，**与窗口标题「个人AI助手」同一层**，
位于窗体右上角）—— 这是 2026-09-23 的第二次调整，它原本在聊天区顶栏（`.chat-toolbar`）。

> **为什么最终落在窗口标题栏**：开关管的是"整个窗口的右半边要不要被占用"，
> 它的作用域**大于聊天区**（右栏是窗口级的一块面积，不属于某条消息流）；
> 而原生标题栏承载不了自绘控件，所以主进程改用 `titleBarStyle: 'hidden'`
> 隐去原生标题栏，标题、拖拽区、开关统一由渲染层的 `.titlebar` 自绘
> （原生交通灯保留，位置由主进程 `trafficLightPosition` 对齐栏高）。
> **副产品**：聊天区顶栏（`.chat-toolbar`）随之删除 —— 它当初只为承载开关而存在，
> 按钮走了就只剩一条 40px 空栏（还白占一条分隔线）。⚠️ 它的两个"恒在"理由
> （避免有会话/无会话时高度跳变、给会话标题留位）一并作废，别再按旧文档把它加回来。

> **该按钮从"两个"收成"一个"（2026-09-23 第一次调整）**：原先顶栏并排两枚**带字**按钮
> （`文件` / `变更`），语义是"开这个视图"。收成一枚图标后的理由：
> 右栏内**本来就能**自己开视图（标签栏「+」菜单 / 欢迎态四入口），顶栏再给一套
> "快捷键式开视图"按钮，等于把"开栏"与"选视图"各给了两个入口 —— 用户会先点「文件」
> 开栏、再在栏里点「+」选「文件」。收成一枚后顶栏只剩一个语义：**这一栏要不要占屏幕**。
> 视图选择留在栏内（就近原则），键盘直达交给 `⌘⇧E` / `⌘⇧G`。

| 入口 | 行为 |
| --- | --- |
| 标题栏图标（`panelRight`，窗体右上角） | **纯开合取反**（`togglePanelOpen`，在 store 里读**当前值**取反）。**不动 `tabs` / `active`** —— 打开时右栏回到上次的样子；从未开过标签则落**欢迎态**（四入口）。`aria-pressed` = `open`，`title` / `aria-label` 随态切换（打开右侧面板 / 收起右侧面板）。**新建任务态下不渲染**（那时没有"这个会话的右栏"） |
| `⌘/Ctrl + Shift + E` | **视图直达**：右栏已开着且正停在「文件」→ 收栏；否则开栏 + 建/激活「文件」视图（监听器在 `RightPanel`，右栏关着时也挂着） |
| `⌘/Ctrl + Shift + G` | 同上，目标视图为「变更」 |
| `Esc` | ① 有「+」菜单 → 只关菜单；② 否则收栏（`setPanelOpen(sid,false)`）。**ask 面板开着 / 审批待处理 / 焦点在输入框或 contentEditable 时不响应** |

> **图标与快捷键刻意不同语义**（不是"两套逻辑实现同一件事"，而是两件事）：
> 图标映射到 `open` **一个字段**，是栏体的开关；快捷键针对的是**某个视图标签**，
> 顺带保留了"再按一次收栏"（这也是除 `Esc` 之外唯一的键盘关闭路径）。
> 对应 store 里三个 action：`togglePanelOpen(sid)`（**取反**，图标用）、
> `setPanelOpen(sid, open)`（**定向**，`Esc` 用）、`togglePanel(sid, view)`（视图直达，
> 快捷键用）。**分居两个组件**：图标在 `TitleBar`、快捷键与 `Esc` 在 `RightPanel`。

> ⚠️ **为什么图标走 `togglePanelOpen` 而不是 `setPanelOpen(sid, !open)`（2026-09-23 回归修复）**：
> 后者把"现在是不是开着"钉死在**渲染那一刻的闭包**里 —— 一旦组件没跟着 store 重渲染
> （订阅断了 / 被 memo / handler 存进 ref / 双实例 store……），就会**每次写同一个值**，
> 症状正是用户实测报的**"点得开、点不关"**。开合状态只该有一个真相来源：`get()` 里的当前值。
> 这个坑的代价不在代码量，而在**它测不出来**（headless 里组件总是正常重渲染），
> 所以有 S20h 那条"同一 JS 任务内连点 3 次必须真取反"的反证断言兜着。


> **「再点一次 = 收栏」而非"关掉这个标签"**：标签是"我打开过什么"的持久记录，
> 开关管的是"这一栏现在要不要占屏幕"。两个语义混在一起，用户会发现自己精心攒的标签
> 被一次误点清空了。

**标题栏自身的硬约束**（改 `.titlebar` 前必读，细节在 `styles/layout.css` 的同名注释）：

| 约束 | 为什么 |
| --- | --- |
| **拖拽区是 `.titlebar-drag` 填充块，不是整条栏**；不变式 = **没有任何 `drag` 矩形与开关相交** | 老写法（整层 drag + 按钮 `no-drag`）依赖浏览器做"父级矩形 − 子级矩形"的差集，而拖拽区是**异步算好缓存给系统**的（`DraggableRegionsChanged` → AppKit `mouseDownCanMoveWindow`）；缓存与 DOM 不同步时按钮那 26×26 就被算成 drag → mousedown 被拿去拖窗 → **`click` 根本不派发**（2026-09-23 实测"点得开、点不关"）。真 Electron 实测：老写法下 `titlebar` / `titlebar-right` **两块** drag 矩形盖着按钮（§7.3.1 的 D9 反证） |
| `.titlebar` 自身**不设** `-webkit-app-region`；拖拽块必须 `align-self: stretch` | 空 div 默认高度 0 ＝ 没有可拖区域（S0p 抓过一次）；`-webkit-app-region` **是可继承属性**（实测 `.titlebar-right` 会继承父级的 `drag`） |
| 内容层必须有 `z-index`（`> * { z-index: 1 }`） | 两段底色的 `::after` 在文档序里排在真实子元素**之后**，同为 relative + auto z-index 时它会盖住右上角的开关（踩过） |
| 底色**分两段**：左 `--sidebar-width` 灰 + 其余白 | 与下面的侧边栏 / 聊天区对齐（原生观感）；macOS 交通灯正好落在灰底上 |
| 标题**居中**（grid `1fr auto 1fr` 两翼等宽） | 与原生标题栏同位，不给用户"标题跑位了"的观感 |
| 栏高 `--titlebar-height: 40px`，与主进程 `TITLEBAR_HEIGHT` **必须同值** | 交通灯位置（`trafficLightPosition: {x:16,y:14}`）与 `titleBarOverlay.height` 都按它算 |
| Windows/Linux 走 `titleBarOverlay`，右侧留白 138px（`.titlebar--overlay`） | 系统的最小化/最大化/关闭按钮压在本层之上；平台判定见 `lib/platform.ts`（**只此一处用 UA**，理由写在文件头） |
| 开关按钮仍显式写 `no-drag` | 现在它的 26×26 里本来就没有 drag 矩形（第一条）；写上是为了**将来有人给 `.titlebar-right` 加 drag 时立刻看得见冲突** |

### 3.4 文件视图

- 数据源：`listRefs`（复用 `13` 篇的 `refs_list` 命令，**零新增后端能力**）。
- 目录树 `buildFileTree(workdir, items)` 纯函数构建；单击目录行展开/折叠。
- 键盘：`role="tree"` + roving tabindex，`↑↓` 移动、`←→` 折叠/展开、`Enter`/空格 打开、
  `Home`/`End` 跳首尾。
- 右键菜单：在系统文件管理器中显示 / 复制路径。
- 五种状态：`disabled > error > loading > empty > 内容`。截断时树尾提示。
- 点文件 → **常驻位**（`origin: 'tree'`）。

### 3.5 文件预览

- 懒读：只有当前激活的**文件标签**才触发 `file_read`（视图标签不预读任何文件）。
- 六种状态：请求未到（loading）→ `reason` 失败态 → `binary` → `too_large`（**整屏替换**，
  因为"半个文件"比"没有文件"更容易误导）→ 正常（可选截断横幅 + 行号槽 + `<pre>`）。
- **单飞行 + 回执自校验**：主进程 `pending` 表按 `kind` FIFO 配对、**不带 request id**
  （`main/index.ts`），所以前端必须自己兜：① 同一时刻只允许一个文件请求在飞；
  ② 回执到达时用 `preview.path === 当前 path` 自校验，不匹配就当"还没到"。

> 为什么不用 `previewPath` 这种"请求时记下期望值"的字段？因为它是**第二个真相源** ——
> 只要有一条路径忘了更新它，就会出现"回执明明是自己要的却被丢弃"或反之。直接比对回执
> 自带的数据，无法说谎。

- 代码区显式 `user-select: text`：全局是 `none`（桌面端拖拽体验），不放开的话**一行都复制不了**。

### 3.6 变更视图

- 四个分组，顺序固定：**冲突 → 已暂存 → 未暂存 → 未跟踪**。按谓词分组，**允许同一文件命中多组**
  （一个文件可以既有暂存改动又有工作区改动）。
- `staged` 的判据是 `f.staged && !f.has_working_changes` —— 光看 `staged` 会把
  "既暂存又改了"的文件同时列进「已暂存」和「未暂存」，看起来像重复。
- 点文件行 → 内联展开 diff（`git_diff`），**同一文件只拉一次**。
- diff 渲染：`+` 绿底 / `-` 红底（GitHub 式代码 diff 约定，与 A 股涨跌配色无关）、
  行号槽、`>3000 行`折叠并提供「显示原始 diff」。
- 行尾「在右栏打开」：用 `git.root` + 相对路径拼绝对路径，开**常驻位**。
- 文件行用 `div role="button"` 而不是 `<button>` —— 行尾要放真按钮，`button` 套 `button` 非法。

### 3.7 会话内点文件链接（改道）

`13` 篇的胶囊点击此前一律 `openInFinder`。本期改道（`MessageItem.tsx` 的 `openRef`）：

| 引用类型 | 行为 |
| --- | --- |
| 文件（`is_dir: false`） | 在右栏**预览位**打开（无激活会话时回退 Finder） |
| 目录（`is_dir: true`） | 系统文件管理器定位（目录没有"预览"这回事，**不产生无效标签**） |
| 附件 chip | 不变，仍 `openInFinder` |

`RefText` / `RefBar` 的 `onOpen` 签名相应从 `(path) => void` 改为 `(path, isDir) => void`。

### 3.8 按会话隔离（本期验收重点）

| 时机 | 行为 |
| --- | --- |
| 切会话 | ① **先 `flushRightPanelPending()` 落盘**（待写状态属于旧会话，带着它切过去会写错桶）；② `keepOnly(新 sid)` 丢掉旧会话的 `live` |
| 回会话 | 后端 `session_history` 带 `right_panel`（首次为 `null`）→ `applySessionUi` **只在桶不存在时**写入 |
| 删会话 | `deleteSessions` / `removeProject` 显式 `dropSessions(ids)`（含撤掉待写盘条目） |
| 断线重连 | `setConnection('connected')` 时 `resetTransient()` —— 断线期间发出的请求**永远不会有回执**，不清掉 loading 就会永久转圈 |

## 四、协议

### 4.1 新增 4 个控制命令

| 命令 | 载荷 | 回执 |
| --- | --- | --- |
| `file_read` | `{path, project_id?, session_id?}` | `file_content`（点对点 `safe_send`） |
| `git_status` | `{project_id?, session_id?}` | `git_status`（点对点） |
| `git_diff` | `{path, staged?, project_id?, session_id?}` | `git_diff`（点对点） |
| `session_ui` | `{session_id, ui}` | **无回包**（fire-and-forget） |

`session_ui` 不发回执、也不 `reply_sessions()` 的原因：它是**高频低价值**的写入（每次点标签都可能写），
回执只会带来流量与竞态。落盘成功与否不影响本轮界面。

### 4.2 为什么回执走 `safe_send` 而不是广播

三个查询类回执都是**点对点**：多窗口下 A 窗口点开一个文件，B 窗口没必要收到一份 `file_content`。
（对比 `permission_changed` 必须广播 —— 盾牌 chip 常驻输入区，多窗口不一致是**视觉事故**；
这两个场景的判据是「状态是否常驻可见」，不是「是否安全」。）

### 4.3 前端 5 处接线（缺一处就静默失效）

新增一条命令必须同时改这 5 个地方，`desktop-agent-feature-add` 技能里有完整清单：

1. `protocols/agentProtocol.ts` —— payload 类型 + `UiEvent` + `ControlKind`；
2. `preload/index.ts` + `index.d.ts` —— 暴露方法；
3. `main/index.ts` —— `ipcMain.handle`；
4. `lib/browserAgent.ts` —— 纯浏览器回退实现；
5. 渲染层调用点。

`session_ui` 是个例外：它在主进程里**直接 `ws.send`**，不进 `pending` 表（进了就会污染
按 kind FIFO 的配对表，让后续同类命令错配）。

### 4.4 `session_history` 载荷新增字段

`payload.right_panel: RPanelPersist | null`（`03` 篇 §2.1）。**两处**都要加 ——
运行中分支与回放分支，漏一处就是"切到执行中的会话后右栏消失"。

### 5.3 `agentStore` 的 6 处挂钩

依赖方向是**单向** `agentStore → rightPanelStore`。`rightPanelStore` **禁止 import `agentStore`** ——
所有 action 都收 `sid` 参数，由调用方传入。这是为了避开循环依赖。

| # | 位置 | 动作 |
| --- | --- | --- |
| 1 | `setConnection` 的 `'connected'` 分支 | `resetTransient()` |
| 2 | `session_history` 分支 | `applySessionUi(sid, payload.right_panel)`（**在 `set()` 之外**调用，保持更新函数纯性） |
| 3 | `switchSession` 开头 | `flushRightPanelPending()` |
| 4 | `switchSession` 的 `set()` 之后 | `keepOnly(sid)` |
| 5 | `removeProject` | 先算 `gone` → 过滤 sessions → `dropSessions(gone)` |
| 6 | `deleteSessions` | `dropSessions(deleted)` |

**宽度**：`RPANEL_MIN_WIDTH=280` / `DEFAULT=360` / `MAX=720`，且 `rpanelMaxWidth()` 要保证
聊天区至少留 `RESERVED_WIDTH=520`（小窗口下右栏不能把主区挤没）。宽度存 `localStorage` 的
`aigent.rpanel.width`，**松手才写**（拖拽过程中写会把 localStorage 变成高频 IO）。

**落盘防抖**：`PERSIST_DEBOUNCE_MS = 400`。`mutateLayout` 是**唯一的布局写入口**，自动排队落盘 ——
散落各处手写 `sessionUi` 调用，早晚会漏一处（表现为"改了但切会话回来没生效"）。
`beforeunload` 时同步 flush 一次。

### 5.5 zustand v5 选择器纪律

`useRightPanelStore((s) => s.liveBySession[sid] || {})` 这种写法会**无限重渲染**
（selector 返回值即 `getSnapshot`，每次新建对象就不相等）。所以有模块级 `EMPTY_LIVE` 常量兜底：

```ts
const EMPTY_LIVE: RPanelLive = { /* 全空 */ }
const live = useRightPanelStore((s) => s.liveBySession[sid] ?? EMPTY_LIVE)
```

`18` 篇里已经踩过同一类坑（§5.4），这里是第二次 —— **凡是 selector 里出现 `?? {}` / `[]` / 对象字面量，
一律先怀疑它。**

### 7.3.1 真实 Electron 窗口实测（Electron 44 + 裸 CDP，**12/12 PASS**）

上一节的 harness 跑在 headless Chromium 里，**结构性测不到拖拽区**：
headless Chromium **不实现** `-webkit-app-region` 的命中改写，CDP 注入的鼠标事件
也**绕过**系统判定（AppKit 的 `mouseDownCanMoveWindow`）—— 也就是说
`electron-probe.js` 里旧版 E12/E13 那句"真鼠标点击在 drag 区内也生效"是**被高估的结论**，
它只证明了 DOM 接线，没证明 OS 判定。所以第三次改动换了个可判定的路子：
**不断言"点得到"，而是断言"OS 没有理由吃掉这次点击"** ——
即几何不变式 *没有任何 `drag` 矩形与开关相交*。

窗口选项与真实应用对齐（`titleBarStyle: 'hidden'` + `trafficLightPosition: {x:16,y:14}`），
渲染 harness 页面（真实 `TitleBar`/`RightPanel` + 桩后端，所以开关真的会渲染出来）：

| # | 断言 | 说明 |
| --- | --- | --- |
| D1 | `.titlebar` 计算 `-webkit-app-region` = `none` | 见 §3.3 硬约束第 1 条 |
| D2 | **没有任何 drag 矩形与开关相交**（`inter = []`） | 拖拽区命中判定的**唯一条件**：交了就 mousedown 变拖窗、`click` 不派发 |
| D3 | 三块拖拽填充块高度 `[39,39,39]` | 空 div 默认 0 高 = 拖不动 |
| D4 | 拖拽覆盖率 `96%` | 修完不能把窗口弄成"拖不动" |
| D5/D6 | 按钮 `no-drag` 但**自身不带 drag 矩形** / 命中测试返回按钮 | 两者不矛盾：`no-drag` 是显式声明，矩形是几何事实 |
| D7/D8 | 栏 `[top=0, 宽 1400, 高 40]` / UA 判为 macOS | 与真实应用同一条分支 |
| **D9** | **反证**：临时把老写法（`.titlebar` 设 `drag`）装回去 → 不变式**立刻变红**，`inter = ['titlebar','titlebar-right']` | 证明 D2 **有辨别力**，不是"永远为真"的空断言。同时暴露老写法的真实形状：**两块** drag 矩形盖着按钮，全靠浏览器做差集，差集一旦失效（缓存/DOM 不同步）点击就丢 |
| D10/D11 | 两次真鼠标点击 → 开 → 关 | 接线在真 Electron 里也通 |
| D12 | 渲染层 0 报错 | —— |

**原生交通灯（本机无法截屏，改由 Electron 源码推导）**：`shell/browser/ui/cocoa/window_buttons_proxy.mm`
的 `redraw`/`getCurrentMargin` 决定 —— 按钮 top = `margin_.y()`、close 的 left = `margin_.x()`，
且"容器高度 = 按钮高 + 2×margin.y"是自洽的，所以 **`{x:16, y:14}` 在 40px 栏里等于：
左内边距 16px、按钮（12pt）垂直居中于 14~26**。`getCurrentMargin` 另有一条分支：
若同时设了 `titleBarOverlay.height`（→ `height_ != 0`）且 `margin.y != 默认值`，
则 y 变成 `height - buttonH - margin.y`（贴底而非居中）—— 所以 **macOS 不要设 `titleBarOverlay`**，
否则交通灯会掉到栏底。

> ⚠️ 残留不确定性（老实说）：① 交通灯位置仍是源码推导（本机没给录屏权限，
> `screencapture` 直接报错）；② 真机点击验证用的是 CDP 注入 —— 系统级命中判定由 **D2 的几何**
> 覆盖，而不是"点了一下确实动了"覆盖。若你手上这台还出现点不动，第一件事是量
> `inter`（见上面那条不变式），而不是猜代码。

harness 与截图在 `/tmp/rpanel-toggle-verify/`（`run.js` + `entry.tsx` + `shot-*.png`）
与 `/tmp/titlebar-drag-probe/`（`main.js` + `probe.js` + `electron-bar-closed.png`），**不进仓库**。
踩过三次坑记在这里（第三条是本次的根因）：

1. 新加的 S13x（开合与内容正交）跑完时右栏是**开着**的，而后面的 S14 用 `⌘⇧E` 开栏 ——
   该快捷键此刻会把它**收掉**（视图直达语义），导致 S15c「切回 A 右栏恢复」假失败。
   **新增用例必须显式复位它依赖的初态**；
2. 标题栏的两段底色用了 `::before` / `::after`，而 `::after` 在文档序里排在**真实子元素之后**
   —— 不给内容层提 `z-index` 时它盖住右上角的开关，表现为"点图标右栏没反应"。
   这次是 harness 的 S1a 先抓到（点完 `open` 仍是 `false`），真机复核；
3. **"点得开、点不关"**（用户实测）：两个原因叠加可能，两条都堵上了 ——
   ① 组件里 `setPanelOpen(sid, !渲染时的布尔)` 把状态钉在闭包里（→ `togglePanelOpen` 读 `get()`）；
   ② 拖拽区写成了"整层 drag + 按钮 `no-drag`"，按钮那 26×26 落在两块 drag 矩形里
   （真机 D9 反证量到了：`['titlebar','titlebar-right']`），是否还能点全看浏览器做差集有没有及时同步
   （→ 拖拽区改成独立填充块，不变式"没有 drag 矩形与开关相交"）。
   **教训**：这类"OS 层吃事件"的 bug 在 headless 里**测不出来**（不实现命中改写）、
   CDP 注入的鼠标事件也**绕过**系统判定 —— 别把"CDP 点了一下有反应"当成真机可用；
   能测的是"OS 有没有理由吃掉它"（几何不变式），而不是"它有没有被吃掉"。
