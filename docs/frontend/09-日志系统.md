# 09 - 日志系统

> 状态：已实施（2026-09-11）。本文档描述桌面端前后端的统一日志方案，
> 作为后续垂直类智能体客户端的开发依据。

## 概念

桌面端由两个长驻进程组成：Electron 主进程（前端壳）与 `ws_bridge.py`（Python 后端）。
此前排障完全依赖 `print` 到 stdout，存在三个问题：

1. **无落盘**：Electron 生产模式拉起的子进程 stdout 无人消费，历史输出丢失；
2. **无结构**：没有时间戳 / 级别 / 来源，事后无法回溯"几点几分发生了什么"；
3. **无兜底**：未捕获异常（尤其线程内异常）直接蒸发，进程崩溃无从查起。

日志系统的目标是：**任何一次运行的关键节点（启动、会话生命周期、模型切换、
turn 执行、工具调用、异常崩溃）都能在文件里按时间线回放**。

## 设计

### 目录与文件

- 目录：`~/.aigent/logs/`（常量 `LOG_DIR` 定义在 `agents/paths.py`，随 `ensure_dirs()` 创建）。
- 文件按**日期**命名，跨天（本地时区）自动切换新文件，无需重启进程：
  - 后端（Python）：`agent_YYYY-MM-DD.log`
  - 前端（Electron 主进程）：`frontend_YYYY-MM-DD.log`

### 行格式

```
2026-09-11 15:30:01 [INFO] [ws_bridge] WS 连接建立: ('127.0.0.1', 52318) (active=1)
2026-09-11 15:30:05 [INFO] [agent] 工具执行完成: session_12 read_file (0.03s, 输出 1024 字符)
```

`时间 [级别] [来源] 消息`。来源（logger name）区分模块：`ws_bridge` / `runtime` /
`agent` / `cli` / `crash`（前端用 tag：`app` / `python` / `ws`）。

### 关键取舍

- **只写文件，不写 stdout**：stdout 是 CLI 交互 / Electron 日志面板的通道，
  `print` 继续承担控制台职责；日志走文件，互不干扰、不产生双份噪音。
- **logging 标准库自实现按日切换**：`DailyFileHandler` 在每次 emit 时比对当前
  日期，跨天即换新文件（append 模式）；不引入额外依赖。logging 框架对 handler
  加锁，多线程（turn 工作线程 / 后台子智能体 / 标题线程）并发写安全。
- **级别可调**：`LOG_LEVEL`（默认 `INFO`）走既有配置链
  （`~/.aigent/config.json` > 环境变量 > 默认值，见 `05-配置与数据目录管理.md`）。
- **日志失败绝不打断业务**：写文件异常由 `handleError` 吞掉；前端 `appendFile`
  失败静默。
- **每条写完即 flush**：后端长驻进程随时可能被 SIGTERM/SIGKILL（Electron
  退出、孤儿看护自杀），不 flush 的话 Python 文件缓冲里的日志会随进程一起
  丢失。曾因此踩坑：`emit` 里误调基类 `Handler.flush()`（访问不存在的
  `self.stream` 属性抛 `AttributeError` 被吞），表现为"前台测试正常、
  服务进程日志随机丢失"——正常退出的进程会自动刷缓冲，掩盖了 bug。
- **崩溃兜底**：后端入口调用 `install_excepthooks()`，把主线程与子线程的
  未捕获异常（含完整 traceback）写入 `[crash]` 来源，进程被强杀前的最后
  一线证据不再丢失。

## 落地

### 后端（Python）

统一入口 `agents/logger.py`：

```python
from logger import get_logger
log = get_logger("agent")   # 任意模块名
log.info("会话切换: session_%d", num)
```

埋点清单（按模块）：

| 模块 | 记录内容 |
| --- | --- |
| `ws_bridge.py` | 后端启动（端口/pid/主模型）、WS 连接建立/断开（含 close_code）、新会话创建（含所选模型）、chat 派发、停止请求、会话切换/清空/重命名/回收/还原/批量删除、模型配置保存与热切换结果（旧→新模型）、回包发送失败、writer 异常、父进程退出随退、状态重放/status_query |
| `session_runtime.py` | 会话状态机（running/background/done/stopped 全链路）、agent 构建（含会话绑定模型）、会话模型重绑、turn 结束（耗时/终态/后台标志）、turn worker 异常、bg watch 启动/取消/结束、bg 续轮与异常 |
| `agent_full_v2.py` | 会话初始化/创建/切换/清空、turn 开始（含用户输入前 100 字符）/结束（含累计 token）、后台续轮、工具执行开始（名称+参数摘要 200 字符）/完成（耗时+输出规模）/后台分发（bg_id）、LLM 调用异常、最大迭代次数强制结束、goal 全部裁决（block/defer/achieved/failed/limit/error）、LLM 绑定热切换（旧→新模型） |
| `agent_cli.py` | CLI 启动（pid/主模型）、未捕获异常兜底 |
| `session_manage.py` | 会话加载/创建、历史文件修复与备份、读写失败、子智能体记录读写失败、上下文压缩完成、元数据索引读写失败、删除/清空失败 |
| `teammate_manager.py` | 队友 spawn/finish、协议状态（shutdown/plan 审批）、idle 认领与超时、LLM 错误 |
| `task_manager.py` | 任务创建/认领/完成/解锁、会话任务板 GC |
| `cron_scheduler.py` | 定时任务加载/注册/取消、执行错误、调度器启动 |
| `llm_config.py` | 模型配置加载（主模型名）、v1→v2 迁移、预置厂商目录更新、解析失败 |
| `context_compact.py` | 压缩 transcript 落盘路径 |
| `subagent_store.py` | 子智能体记录删除/写入/迁移失败 |

> 历史清理（2026-09-11 二次改造）：上述模块中原有的调试 `print`（含 ANSI
> 颜色输出）已全部转为日志调用或删除（与相邻 log 重复的）。现在后端
> stdout 不再有调试噪音；CLI 的用户交互输出（`agent_cli.py` 的命令回显、
> `Agent._print` 输出通道）保留 print，属正当 UI 而非调试。

### 前端（Electron 主进程）

`frontend/src/main/logger.ts` 导出 `flog.info/warn/error(tag, msg)`，
按日期异步 append 到 `~/.aigent/logs/frontend_YYYY-MM-DD.log`。

埋点清单：

| 文件 | 记录内容 |
| --- | --- |
| `index.ts` | 应用启动（Electron/Node 版本、pid）、所有窗口关闭、before-quit 清理、Python 后端状态变化（starting/running/crashed/stopped）、WS 连接状态变化 |
| `pythonManager.ts` | 拉起后端（解释器路径、脚本、端口、pid）、后端进程退出（code，正常 info / 非零 error） |
| `agentWS.ts` | WS 连接成功、连接断开（code/reason/wasClean，区分"后端未就绪的首连失败"与"运行中断开"） |

### 验证方式

```bash
# 启动桌面端后查看当日日志
ls ~/.aigent/logs/
tail -f ~/.aigent/logs/agent_$(date +%F).log
tail -f ~/.aigent/logs/frontend_$(date +%F).log
```

一次完整的"启动 → 新会话 → 对话一轮"在后端日志里应能看到：
`后端启动 → WS 连接建立 → 新会话创建 → chat 派发 → agent 构建完成 →
turn 开始 → 工具执行开始/完成… → turn 结束 → turn 结束(session)`。
