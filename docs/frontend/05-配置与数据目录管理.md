# 配置与数据目录管理

> 本文档描述桌面智能体客户端的**配置来源与数据目录组织**。核心结论：配置不再放项目根 `.env`，而是迁移到用户级目录 `~/.aigent/`（对齐 Claude Code `~/.claude`、Codex `~/.codex` 的主流做法）；`.env` 仅作遗留兜底。按「概念 → 设计 → 落地」组织。

## 一、概念：为什么配置放用户目录

桌面级 AI Agent 产品普遍把「应用自身运行所需的数据」放在用户主目录下的私有目录，而非项目根目录，原因：

1. **配置是用户级的，不是项目级的**：API Key、模型偏好、工具超时等与具体项目无关，跨项目应复用同一份配置。
2. **项目根目录应只放「被操作的对象」**：仓库是 agent 干活的对象（源码、任务文件），配置混入会污染仓库、有密钥入库风险。
3. **多实例/多项目共用**：同一用户可同时开多个项目，配置应全局共享，运行时数据按项目隔离。
4. **云同步与权限**：用户目录天然支持权限控制（`0600` 密钥文件）、可整体备份/迁移/云同步。

主流参照：

| 产品           | 用户级目录                        | 配置格式                                  |
| ------------ | ---------------------------- | ------------------------------------- |
| Claude Code  | `~/.claude/`                 | `settings.json` + `.credentials.json` |
| OpenAI Codex | `~/.codex/`                  | `config.toml` + `auth.json`           |
| Trae         | `~/.trae/`（国内 `~/.trae-cn/`） | JSON                                  |

共性：**用户级配置在** **`~/.xxx/`，密钥独立文件（0600）或系统钥匙串，环境变量仅作 CI/临时覆盖**。

## 二、设计：\~/.aigent 目录结构

```
~/.aigent/                          # 用户级应用 home（AIGENT_HOME）
├── config.json                     # 用户级非敏感配置（扁平键，键名与 .env 一致）
├── credentials.json                # 密钥（OPENAI_API_KEY 等，权限 0600）
├── llmconfig.json                  # 大模型配置（多服务商模型，含 api_key，权限 0600，详见 06 篇）
├── skills/                         # 用户级技能（← 原 WorkSpace/HomeDir/skills）
├── worktrees/                      # worktree 挂载（← 原 WorkSpace/HomeDir/worktrees）
└── mcp/                            # MCP 配置（← 原 WorkSpace/HomeDir/mcp）
    └── mcp_servers.json
```

**保持不变**：工作路径 `WORKDIR`（`WorkSpace/task1`）及其下所有运行时数据目录（`.chathistory/.transcripts/.task_outputs/.memory/.todo/.tasks/.team/.inbox/.workflow/.scheduler`）仍在项目内，本方案不迁移（见「未来方向」）。

### 分层配置优先级（高 → 低）

1. 真实环境变量（系统注入 / CI / 前端 spawn 透传）
2. 项目级 `[项目根]/.aigent/config.json`（可选覆盖，已 gitignore）
3. 用户级 `~/.aigent/config.json`
4. `.env`（遗留兜底）
5. 代码内默认值

### 密钥管理

- 密钥（`*_API_KEY` / `*_TOKEN` / `*_SECRET` 结尾的键）单独存 `~/.aigent/credentials.json`，权限 `0600`。

- 与 config.json 分离，避免「非敏感配置」文件误入库/误分享时连密钥一起泄露。

- 未来可平滑升级为 macOS 钥匙串（credentials.json 结构保持不变）。

## 三、落地：启动加载流程

### 模块职责

- `agents/config.py`（新增）：应用 home 常量 + 配置加载 + 一次性迁移。

  - `AIGENT_HOME` / `CONFIG_FILE` / `CREDENTIALS_FILE` 常量。

  - `load()`：按优先级把配置合并进 `os.environ`（`setdefault`，不覆盖已存在变量）。

  - `migrate_legacy()`：把旧 `WorkSpace/HomeDir/{skills,worktrees,mcp}` 搬迁到 `~/.aigent/`；无 `config.json` 时从 `.env` 生成种子（非密钥键 → config.json，密钥 → credentials.json 0600）。幂等。

- `agents/paths.py`：`SKILLS_DIR` / `WORKTREE_DIR` / `MCP_DIR` / `MCP_CONFIG` 改指 `~/.aigent/` 下；`WORKDIR` 及运行时目录常量**不变**。`ensure_dirs()` 导入期调用 `migrate_legacy()`。

- 依赖方向：`config.py` 不 import `paths.py`（避免循环依赖），`paths.py` 单向依赖 `config.py`。

### 加载顺序（load()）

```
真实环境变量 ──load_dotenv(override=False)──► .env 只填空缺
    │
    ├─► ~/.aigent/config.json     setdefault（不覆盖真实环境变量）
    ├─► ~/.aigent/credentials.json setdefault
    └─► [项目根]/.aigent/config.json setdefault（覆盖用户级）
```

业务模块**零改动**：继续 `os.environ.get(KEY, default)` 内联读取。

### 入口调用点

| 入口                     | 调用方式                                       |
| ---------------------- | ------------------------------------------ |
| `agents/agent_cli.py`  | `main()` 首行 `load_config()`（Agent 实例化前）    |
| `agents/ws_bridge.py`  | 模块顶部 `load_config()`（Electron spawn 后立即自举） |
| `agents/llm_manage.py` | `load_dotenv(override=False)`（不覆盖已注入值）     |

### 一次性迁移（首次运行自动执行）

- `WorkSpace/HomeDir/skills`、`worktrees`、`mcp` → `~/.aigent/` 对应目录（`rename`，目标已存在则跳过）。

- `.env` → 生成 `config.json` 种子 + `credentials.json`（0600），`.env` 仍兜底。

- 迁移后打印日志说明新位置；二次运行幂等。

### 全新首次启动（\~/.aigent 为空）

`~/.aigent` 不存在（新机器/新用户）时，`migrate_legacy()` 走「全新环境」分支：

1. 预建目录骨架：`~/.aigent/skills`、`worktrees`、`mcp`（幂等）。
2. 无 `.env` 可播种 → 生成空 `config.json`（`{}`），参数全部走代码默认值。
3. 打印首次启动引导（非敏感配置 / 密钥文件位置）。
4. 密钥缺失时不裸崩：`llm_manage.py` 报错会带出 `~/.aigent/credentials.json` 路径与「或设置同名环境变量」的指引。
5. 二次启动不再打印首次引导（幂等）。

## 四、前端影响

- Electron 主进程 spawn 后端时 `cwd = 仓库根`、`env = { ...process.env, AGENT_WS_PORT }`，且解释器加 `-u` 无缓冲参数（见 `frontend/src/main/pythonManager.ts`）——后端 `ws_bridge.py` 自举配置后与 CLI 入口行为一致；`-u` 保证 `WS server listening` 等 banner 即时输出，`readyProbe` 才能可靠判定后端就绪（Python 输出到 pipe 默认全缓冲，缺失时 UI 会误判后端未启动/崩溃）。

- `AGENT_WS_PORT` 仍走环境变量透传。

- 可选增强（未来）：Electron 主进程直接读 `~/.aigent/config.json` 获取 UI 偏好（模型列表、主题等），无需新增 ws 协议。

## 五、未来方向：工作目录可选化

当前 `WORKDIR = ROOT_DIR/"WorkSpace/task1"` 为硬编码。后续改为配置项（如 `~/.aigent/config.json` 中 `WORKDIR` / `WORKSPACE_ROOT` 键），支持：

- 多任务/多项目各自指定独立 workspace 根（对齐 Codex `--cd` / TraeWork 会话工作区）。

- 运行时数据目录（`.chathistory` 等）随 WORKDIR 走，届时一并从项目内迁出至 `~/.aigent/projects/<项目slug>/`（对齐 Claude Code `~/.claude/projects/` 模型）。

- 沙盒校验：WORKDIR 必须位于配置允许的根目录下（安全约束）。
