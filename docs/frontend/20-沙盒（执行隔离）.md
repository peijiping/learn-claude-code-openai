# 沙盒（执行隔离）

> 一句话：**权限管控（17 篇）是策略层——决定"允不允许、要不要问"；沙盒是执行层——决定"进程真跑起来时 OS 层面实际能碰什么"。** 前者靠静态分析参数（可被变量拼接/脚本中转绕过），后者是操作系统级的墙。两层互补，缺一不可。

## 一、概念

### 1. 为什么权限管控挡不住，还需要沙盒

17 篇 §3.3 已如实声明："bash 路径 token 扫描是纵深防御而非绝对墙，绝对墙只有系统级沙箱"。权限管控挡不住的风险：

| 风险 | 为什么策略层挡不住 |
| --- | --- |
| 变量拼接 / 脚本中转读敏感文件 | `cat $HOME/.ssh/id_rsa`、base64 解码后执行——静态 token 匹配全部失效；`full_access` 模式下更是全放行 |
| 网络外呼 | bash 里 `curl`/`wget`/`python -c 'requests...'` 不在工具参数里，判定层看不见 |
| 密钥经环境变量泄露 | 子进程默认继承父进程全部 env，权限管控管不到子进程内部 |
| 写越界（绕过 safe_path 的进程） | `bash -c` 内部再起进程、脚本内 `cd` 后写文件，`safe_path` 只拦**工具参数** |

### 2. 覆盖范围：为什么只沙盒 `run_bash`

- **bash 是唯一的风险面**：它是唯一 spawn 子进程的工具，也是唯一的网络出口（项目没有 web_fetch 等网络工具）。
- **文件工具不需要**：`run_write/run_edit/run_read` 在 Python 进程内执行、不 spawn 子进程，已被 `safe_path`（有效目录集硬墙）+ PermissionGate 双层拦截。用沙盒包裹进程内文件操作是纯开销零收益。
- 资源限制（CPU/内存/fork）沙盒不管（Seatbelt/bwrap 都不是干这个的），本期不做。

### 3. 与权限管控的分层关系

- **判定层（permission.py）零改动**：沙盒在工具执行路径（`ToolRegistry.run_bash`）之下，判定层说"允许执行"≠ 执行不受限。
- **full_access 模式同样走沙盒**：免审批不免墙——这正是沙盒的价值（对齐 Codex 的"审批×沙箱双维度"）。
- **沙盒拒绝 ≠ 权限拒绝**：沙盒拦截是执行期失败，以工具结果字符串（`Error: 命令执行失败，返回码 N` + 沙盒提示）返回给模型，走现有 run_bash 错误契约，不触发审批卡片。

## 二、设计

### 1. 核心机制：用户可编辑的持久化模板 + 占位符

沙盒策略不硬编码——**落盘为模板文件，用户在设置→沙盒页直接编辑**：

```
~/.aigent/sandbox/
├── seatbelt.sb      # macOS Seatbelt profile 模板
└── bwrap_args.txt   # Linux bubblewrap 参数模板（每行一个参数）
```

- 首次访问自动写入默认模板（**幂等，绝不覆盖用户已有文件**）；读盘失败兜底用默认内容。
- **占位符**解决"静态文件 vs workdir 每会话不同"的矛盾，执行时由后端按会话动态替换：

| 占位符 | 含义 | Seatbelt 中 | bwrap 中 |
| --- | --- | --- | --- |
| `{{WORKDIR}}` | 本会话主工作区 | 值替换（模板里已写好 `subpath` 语法） | 值替换 |
| `{{EXTRA_WRITABLE}}` | 会话批准的额外可写目录 | **段展开**：每目录一行 `(allow file-write* (subpath "…"))`；空集=空串 | **段展开**：每目录一行 `--bind <dir> <dir>`；空集=空串 |
| `{{TMPDIR}}` | 系统临时目录 | 值替换 | 值替换 |
| `{{HOME}}` | 用户主目录 | 值替换 | 值替换 |
| `{{COMMAND}}` | 要执行的命令 | 不使用（命令经 argv 传入） | **整行替换且保持单参数**（`bash -c` 语义要求，含空格/换行也绝不切分） |

- **所有路径替换前先 `Path.resolve()` 规范化**：macOS `/var→/private/var`、`/tmp→/private/tmp` 符号链接会让 Seatbelt 的 `(subpath ...)` 匹配落空（实施时踩坑，见 §5）。
- **必需占位符校验**：seatbelt 需 `WORKDIR/EXTRA_WRITABLE/TMPDIR/HOME`，bwrap 另需 `COMMAND`。保存时校验（缺则拒存报错）；执行前再体检，缺则 error log + 裸跑降级（绝不因模板问题打死本轮）。

### 2. 平台矩阵与后端抽象

```
SandboxBackend 协议:  is_available() + run(command, cwd, workdir, extra_writable, timeout)
                      run() 返回与 subprocess.run 同构的 CompletedProcess（text 已解码）
get_backend():        SANDBOX_BACKEND 强制指定；auto 按平台顺序探测
```

| 平台 | 后端 | 机制 | 不可用时 |
| --- | --- | --- | --- |
| macOS (darwin) | `SeatbeltBackend` | `sandbox-exec -f <profile> /bin/bash -c <cmd>`，系统自带零依赖 | 降级裸跑 |
| Linux | `BubblewrapBackend` | `bwrap --ro-bind / / ...`（需安装 bubblewrap；`is_available()` 含试跑探测） | 降级裸跑 |
| Windows / 未知 | 无 | 无轻量原生方案（AppContainer 过重） | 降级裸跑 |

**降级统一策略**：已启用但无后端 → 裸跑 + 每进程一次 warning（诚实降级，不 brick 产品）；开关关闭/off → 静默裸跑。bwrap 探测含一次真实试跑（`bwrap --ro-bind / / /bin/true`），userns 被禁（常见于容器内）自动判不可用，结果每进程缓存。

### 3. 两个后端的默认模板语义

**macOS Seatbelt（`seatbelt.sb`）**——allow-by-default + 定向 deny（deny 后跟 allow 例外）：

```lisp
(version 1)
(allow default)
(deny file-write*)
(allow file-write* (subpath "{{WORKDIR}}") (subpath "{{TMPDIR}}") (subpath "/private/tmp"))
{{EXTRA_WRITABLE}}
; /dev 设备回环（git/很多 CLI 依赖 /dev/null、/dev/tty、/dev/fd/*）
(allow file-write* (literal "/dev/null") (literal "/dev/tty") (subpath "/dev/fd"))
(deny network*)
(allow network* (local ip))
(deny file-read* (subpath "{{HOME}}/.ssh") (subpath "{{HOME}}/.aigent"))
```

- 写：仅工作区 ∪ 临时目录 ∪ 额外目录 ∪ /dev 设备；其余 `Operation not permitted`
- 网络：默认全断（`curl` DNS 解析即失败，返回码 6）；回环始终放行（本地 IPC）
- 敏感读：`~/.ssh`、`~/.aigent` 不可见；放行网络 = 用户删 `(deny network*)` 行

**Linux bubblewrap（`bwrap_args.txt`）**——ro-bind 全根 + 定向 bind/tmpfs：

```
--die-with-parent / --new-session / --unshare-ipc
--dev-bind /dev /dev --proc /proc --ro-bind / /
--bind {{WORKDIR}} {{WORKDIR}}
{{EXTRA_WRITABLE}}
--tmpfs /tmp --tmpfs {{TMPDIR}}
--tmpfs {{HOME}}/.ssh --tmpfs {{HOME}}/.aigent
-- /bin/bash -c {{COMMAND}}
```

- 写越界 = 根只读（`Read-only file system`），等价 Seatbelt 语义；敏感读 = `--tmpfs` 覆盖（读不可见）
- 网络 = `--unshare-net` 行；**删行放行是全放（含回环）**——比 Seatbelt 粗，平台差异如实写明
- 参数逐行 `shlex.split`（支持引号路径）；`{{COMMAND}}` 行整行替换为单参数

### 4. 配置项与热生效

config.json（`~/.aigent/config/config.json`）扁平键，`.env.example` 有注释示例：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `SANDBOX_ENABLED` | `"1"` | 总开关，**设置→沙盒页控制** |
| `SANDBOX_BACKEND` | `auto` | `auto/seatbelt/bwrap/off`，高级项不进 UI |

**热生效关键**：`config.load()` 走 `os.environ.setdefault`（不覆盖已有值），重跑 load() 不会生效。因此：

- 业务侧（`sandbox.py`）**每次使用时读 env**，不缓存模块常量；
- 设置页保存后 `ws_bridge._save_sandbox_enabled()` 写盘 + **直接覆写 `os.environ["SANDBOX_ENABLED"]`**（同 llm_config.py 热切换先例）——下一条 bash 命令立即按新开关执行，无需重启。

### 5. WS 协议（`sandbox_config_get` / `sandbox_config_save`）

放在 `permission_config` 命令旁（ws_bridge.py）。**点对点信封** `sandbox_config`（只回发起窗口不广播，同 `permission_config` 理由）：

```jsonc
// sandbox_config_get → 回执：
{ "platform": "darwin", "backend": "seatbelt", "backend_available": true,
  "sandbox_enabled": true,
  "seatbelt_profile": "<seatbelt.sb 内容>", "bwrap_args": "<bwrap_args.txt 内容>",
  "seatbelt_path": "/Users/x/.aigent/sandbox/seatbelt.sb",
  "bwrap_path": "/Users/x/.aigent/sandbox/bwrap_args.txt" }

// sandbox_config_save（字段部分更新，只带要改的）→ 回执同构，另带 applied/errors：
{ "sandbox_enabled": true }                       // 开关：写盘 + env 覆写热生效
{ "seatbelt_profile": "..." }                     // 模板覆写；缺占位符拒存 → errors
{ "bwrap_args": "..." }
{ "reset": "seatbelt" | "bwrap" }                 // 恢复默认模板
```

get 与 save 回执**同构**（save 多 `applied/errors`），前端整份替换 store（无需 merge，对比 permission_config 的"补丁非快照"契约）。

### 6. 前端：设置弹窗「沙盒」tab

`SettingsModal.tsx` NAV 增 `sandbox`（权限之后）。`SandboxSettings.tsx` 布局：

```
┌─ 启用沙盒 [开关] ─────────────────────────────┐
│   副文案：限制在项目目录内/无法访问网络与敏感文件/  │
│   立即生效/完全访问模式下同样生效                 │
│ ● 当前平台 macOS · Seatbelt 可用，沙盒生效中     │  ← 状态行（可用绿点/不可用琥珀▲）
│ [保存失败时的错误条（红底，内联展示）]             │
├─ macOS · Seatbelt profile [当前平台] ─────────┤
│   配置文件 ~/.aigent/sandbox/seatbelt.sb …      │
│   占位符说明行                                  │
│   [等宽 textarea 编辑器 rows=14]                │
│   [保存] [恢复默认模板]                          │
├─ Linux · bubblewrap 参数 [每行一个] ───────────┤
│   （同构编辑器；当前平台分区高亮+边框，双分区都展示）│
└──────────────────────────────────────────────┘
```

交互约定：

- **开关即改即存**（toggle 直接发 save，无独立保存按钮）；两个编辑器各带「保存 / 恢复默认模板」，dirty（草稿≠回执）才可保存。
- **数据流照搬权限页范式**：draft → store（`saveSandboxConfig`）→ browserAgent → WS → 回执整份重置 draft（权威源）。保存失败回滚 = 回执重置 + 内联错误条。
- **错误不 toast**：模板缺占位符等校验错误要对着改文本，内联展示（同 18 篇 §3.3 理由）。
- 打开 tab 懒加载（`openSettings` 里 `if (tab === 'sandbox' && !get().sandboxConfig)`）；关闭设置清缓存（可能被别的窗口改过）。

前端四层链路：`agentProtocol.ts`（`sandbox_config_get/save` ControlKind + `sandbox_config` 事件 + `SandboxConfigResult/SandboxConfigSavePayload`）→ `main/index.ts`（`agent:sandboxConfigGet/Save` IPC，只透传不校验）→ `preload`（`sandboxConfigGet/Save`）→ `browserAgent.ts` → `agentStore.ts`（`sandboxConfig/sandboxSaving` state + `case 'sandbox_config'` + 两 action）。

### 关键取舍

- **策略细节进模板、不进 config 键**：网络放行/敏感读屏蔽直接编辑模板文件，避免"config 键 + 模板"两处策略源漂移；config.json 只留总开关与后端选择。
- **不做全 deny-by-default**：全 deny 会瞬间打爆合法命令（git/python 写缓存），违背轻量产品体验。
- **sandbox-exec 已被 Apple 标记 deprecated**：但仍随系统分发、无替代 API，Claude Code 等业界产品均在用，接受此风险。
- **Windows 本期不实现隔离**：诚实降级 + 状态行明示"暂不支持"，UI 不假装有沙盒。
- **资源限制/env 过滤不做**：沙盒已挡敏感读，env 泄露风险大幅缓解；CPU/内存限制是 Job Object/cgroups 的活，后续增量。

## 五、实施记录（2026-09-23）

按本篇方案实施完成，实测揪出两个坑：

1. **符号链接坑（险些"工作区内也被拦"）**：macOS `tempfile.mkdtemp()` 返回 `/var/folders/...`，而真实路径是 `/private/var/folders/...`；Seatbelt 的 `(subpath "/var/...")` 对写入真实路径的请求**不匹配**，表现为工作区内 `echo > x` 都报 Operation not permitted。修复：占位符替换前所有路径统一 `Path.resolve()`。**教训：传给 Seatbelt/bwrap 的路径必须规范化，绝不能直接用未解析的 tmpdir/workdir。**
2. **/dev/null 坑（git 全挂）**：默认模板 `(deny file-write*)` 把 `/dev/null` 也禁了——git 一切命令 `fatal: could not open '/dev/null' ...: Operation not permitted`（返回码 128）。修复：默认模板补 `(allow file-write* (literal "/dev/null") (literal "/dev/tty") (subpath "/dev/fd"))`。**教训：deny-by-exception 的 profile 必须先用高频 CLI（git/python/node）冒烟，再拦越界。**
3. 另注意：默认模板是**首次访问落盘**的，已有旧模板不会被自动更新（设计如此——不覆盖用户文件）；升级默认模板需删除 `~/.aigent/sandbox/` 下旧文件或在设置页「恢复默认模板」。
